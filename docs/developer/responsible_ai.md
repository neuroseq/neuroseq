# Responsible use of AI

This guidance adapts the principles in
[fastplotlib/claude-skills: Scope, Responsibility & Scientific Integrity](https://github.com/fastplotlib/claude-skills#scope-responsibility--scientific-integrity)
to NeuroSeq development.

## Scope

AI tools can assist with implementation, documentation, and routine coding.
They cannot establish whether a model, analysis, or visualization answers the
scientific question. Use them for work whose expected behavior you can assess;
seek domain expertise when you cannot define a meaningful correctness check.

## Responsibility

Contributors remain responsible for every change they submit, including code
generated by AI. Review the implementation, verify assumptions, and run the
relevant [tests](testing.md). Fluent explanations and plausible output can hide
invented APIs, altered requirements, or unsupported scientific claims.

## Scientific integrity

Code that runs and figures that look convincing can still misrepresent an
experiment. Invalid input also remains invalid after AI-assisted processing.
Check results against independently established expectations:

- Verify array shapes, physical units, sampling rates, and time alignment.
- In NeuroSeq, check neuron identifiers across imported data, stimulus arrays,
  and recordings, and confirm stimulation amplitudes and durations.
- Inspect axis labels, color scales, and display limits for misleading mappings
  or hidden values.
- Compare simulation and analysis output with known cases or reference data;
  software tests alone do not establish biological validity.

Record the assumptions and validation evidence needed to reproduce the result.
If you cannot explain how you would detect an error, obtain expert review before
relying on the output for a scientific conclusion.
