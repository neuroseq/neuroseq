rheobase_dynamic_input_routine — "Minimal stimulus for spiking (rheobase)" Design dynamic input routine
=======================================================================================================

A second Design dynamic input routine, sitting alongside the existing
"Targeted STDP synaptic strength" one. It answers a single question for one
chosen neuron: what is the smallest stimulus amplitude that makes it fire an
action potential (its rheobase)? It does this closed-loop — append a probe
pulse of amplitude A to the neuron's stim column, run Brian2 forward over the
pulse, check whether the neuron spiked, and search A (bracket + bisection)
until the spiking threshold is pinned to a tolerance. The live output is a
"rheobase plot": spike count vs. tested amplitude, with the converged rheobase
marked.

This reuses the closed-loop machinery already built for the STDP routine:
the `simulation_requested(float)` signal → threaded Brian2 run → completion
callback pattern, the append-block-and-run-forward model, the separate plot
window, the scrollable-parameters panel with the wheel guard, the stim-array
info header, and the Clear button. See `src/neuroseq/input_designer_dialog.py`
as the reference implementation and mirror its structure.

Files to change:
    src/neuroseq/stim_editor.py          (routine list + dispatch + sim-callback fan-out)

Files to create:
    src/neuroseq/rheobase.py             (pure spike-detection + search step, no Qt)
    src/neuroseq/rheobase_dialog.py      (RheobaseDialog — closed-loop Qt dialog)
    tests/test_rheobase.py               (pure-function tests)
    tests/test_rheobase_dialog.py        (Qt closed-loop tests, patterned on test_input_designer_dialog.py)

────────────────────────────────────────────────────────────────────────────────────────────
WHAT "RHEOBASE" MEANS HERE
────────────────────────────────────────────────────────────────────────────────────────────

Rheobase = the minimum stimulus amplitude that elicits at least one spike, for
a FIXED pulse duration. It is a property of a single neuron driven directly, so
there is ONE neuron ID: the same index is both the stim-array column that
receives the pulse and the trace row whose voltage is checked for a spike.

Amplitude is in the stim array's own units (whatever the injected quantity is —
current, conductance, optogenetic power). The routine never assumes a unit; it
just searches the numeric amplitude and reports it with the array's unit label,
the same way the STDP routine treats `Pulse amplitude`.

The strength–duration curve (threshold vs. pulse duration) is a NON-GOAL here
(see NON-GOALS). This routine finds one rheobase for the one configured pulse
duration.


────────────────────────────────────────────────────────────────────────────────────────────
PURE HELPERS — src/neuroseq/rheobase.py (new, no Qt)
────────────────────────────────────────────────────────────────────────────────────────────

Keep the numeric core out of Qt so it is cheaply testable, mirroring how
`stim_patterns.py` is split from `stim_pattern_dialog.py`.

1.  count_spikes(trace_mv: np.ndarray, threshold_mv: float = -20.0) -> int

    Count upward threshold crossings: samples where trace goes from
    < threshold_mv to >= threshold_mv. Returns 0 for an empty/too-short trace.
    Rationale: a plateau above threshold counts once, not once-per-sample. Use
    the shared `_to_mv` from `neuroseq.resources.analysis_plugins.epsp_amplitudes`
    at the call site to normalise units before calling this; `count_spikes`
    itself takes already-in-mV data.

        crossings = np.flatnonzero((trace_mv[:-1] < threshold_mv)
                                   & (trace_mv[1:] >= threshold_mv))
        return int(crossings.size)

2.  next_bracket(low: float, high: float, mid: float, spiked: bool)
        -> tuple[float, float]

    One bisection update. `low` is the highest amplitude known NOT to spike,
    `high` the lowest known TO spike, `mid` the amplitude just tested.
        if spiked:  return (low, mid)      # threshold is <= mid
        else:       return (mid, high)     # threshold is > mid

3.  bisection_converged(low: float, high: float, tol: float) -> bool
        return (high - low) <= tol

These are trivial but testing them pins the search invariants and lets the Qt
test focus on wiring.

────────────────────────────────────────────────────────────────────────────────────────────
SEARCH — the closed-loop state machine
────────────────────────────────────────────────────────────────────────────────────────────

State on the dialog:
    self._running: bool
    self._awaiting_simulation: bool
    self._phase: str            # "idle" | "probe_max" | "probe_min" | "bisect"
    self._iteration: int
    self._low: float            # highest amplitude known NOT to spike
    self._high: float           # lowest amplitude known to spike
    self._pending_amplitude: float          # amplitude of the block now running
    self._pulse_onset_seconds: float        # onset time of the pending pulse
    self._samples: list[tuple[float, int]]  # (amplitude, spike_count) tested, in order
    self._rheobase: float | None

start():
    refresh(); guard project / stim modifier present (log + return if not);
    guard trace available — if the trace combo is empty, prompt for an initial
    simulation to create the trace monitor exactly like the STDP dialog's
    "Create stimulation trace monitor" flow (phase "initialize_trace" → emit →
    on finish, refresh and begin). Reuse that code path verbatim.
    Validate: max_amplitude > min_amplitude (else _finish with a message).
    Reset state; self._low = min_amplitude; self._high = max_amplitude.
    Then probe the MAX first to confirm a spike is reachable:
        self._phase = "probe_max"; self._probe(max_amplitude)

_probe(amplitude):
    Build a block (see BLOCK LAYOUT), append it, record onset time,
    set self._pending_amplitude, run to the end of the block.

simulation_finished():
    if not running / not awaiting: return; clear awaiting.
    if phase == "initialize_trace": refresh; begin as in start(); return.
    Measure spikes for self._pending_amplitude (see SPIKE MEASUREMENT).
    Append (amplitude, spike_count) to self._samples; update the plot.
    Dispatch on phase:

      probe_max:
        if spike_count == 0:
            _finish("No spike at the maximum amplitude "
                    f"{max:g} {units}; increase the range."); return
        self._high = max_amplitude
        self._phase = "probe_min"; self._probe(min_amplitude); return

      probe_min:
        if spike_count > 0:
            self._rheobase = min_amplitude
            _finish(f"Neuron spikes already at the minimum amplitude "
                    f"{min:g} {units}; rheobase <= minimum."); return
        self._low = min_amplitude
        self._phase = "bisect"; self._bisect_step(); return

      bisect:
        spiked = spike_count > 0
        self._low, self._high = next_bracket(self._low, self._high,
                                             self._pending_amplitude, spiked)
        self._bisect_step()

_bisect_step():
    if bisection_converged(self._low, self._high, tolerance):
        self._rheobase = self._high     # smallest confirmed spiking amplitude
        self._update_plot()             # draw the rheobase marker
        _finish(f"Rheobase ≈ {self._high:g} {units} "
                f"(bracket [{self._low:g}, {self._high:g}])."); return
    if self._iteration >= max_iterations:
        self._rheobase = self._high
        _finish("Maximum iterations reached; "
                f"rheobase ≈ {self._high:g} {units}."); return
    self._iteration += 1
    mid = 0.5 * (self._low + self._high)
    self._probe(mid)

Log each probe: e.g. "Probe 3: amplitude 2.500 mV → 1 spike" /
"→ no spike". Keep the numbers to a few significant figures.


────────────────────────────────────────────────────────────────────────────────────────────
BLOCK LAYOUT — one probe = rest + pulse + observe
────────────────────────────────────────────────────────────────────────────────────────────

For stim `dt` seconds:
    recovery_n = max(1, round(recovery_ms / 1000 / dt))     # rest BEFORE the pulse
    pulse_n    = max(1, round(pulse_ms   / 1000 / dt))
    tail_n     = max(1, round(response_window_ms / 1000 / dt))
    samples    = recovery_n + pulse_n + tail_n
    block = np.zeros((samples, stim.values.shape[1]), np.float32)
    block[recovery_n : recovery_n + pulse_n, neuron_id] = amplitude
    block_start = self._append_block(block)          # reused helper
    self._pulse_onset_seconds = (block_start + recovery_n) * dt
    self._run_to_sample(block_start + samples)

The generous `recovery_n` lead matters: the framework never resets neuron
state between blocks, so each probe must start from rest for the threshold to
be meaningful. A neuron that just fired needs time to repolarise; 200 ms
default is safe for the example models but is user-tunable.


────────────────────────────────────────────────────────────────────────────────────────────
SPIKE MEASUREMENT
────────────────────────────────────────────────────────────────────────────────────────────

    trace = project.get_data(cmb_trace.currentText(), TraceData)
    (guard None → _finish with a message)
    row = np.flatnonzero(trace.indices == neuron_id)
        (empty → _finish f"Neuron {neuron_id} is not recorded in the trace.")
    trace_mv = _to_mv(trace.traces[int(row[0])], trace.units)
    dt_ms = 1000.0 * trace.dt
    onset_ms  = 1000.0 * self._pulse_onset_seconds
    start = max(0, int(np.floor(onset_ms / dt_ms)))
    stop  = min(trace_mv.size,
                int(np.ceil((onset_ms + response_window_ms) / dt_ms)) + 1)
    spike_count = count_spikes(trace_mv[start:stop], threshold_mv)

`_to_mv` is imported from the EPSP plugin
(`neuroseq.resources.analysis_plugins.epsp_amplitudes`), same as the STDP
dialog. It raises ValueError for a non-voltage trace — catch it and `_finish`
with the message, do not crash.

THE RHEOBASE PLOT
────────────────────────────────────────────────────────────────────────────────────────────

One MatplotlibWidget in the plot window, two stacked axes sharing nothing
(different x units), created like the STDP dialog's gridspec:

  Axis 1 — "Rheobase" (the headline plot):
     x = tested amplitude (array units), y = spike count.
     Plot the (amplitude, spike_count) points from self._samples SORTED by
     amplitude. Draw non-spiking points as open markers and spiking points as
     filled markers (or two scatter calls). When self._rheobase is not None,
     draw a vertical dashed line at that amplitude and annotate it
     ("rheobase ≈ …"). y-axis label "Spikes"; x-axis label
     f"Stimulus amplitude ({units})".

  Axis 2 — "Search" (convergence trajectory):
     x = iteration index (1..N), y = tested amplitude, line+marker in probe
     order (self._samples order, NOT sorted). Optionally shade the current
     [low, high] bracket. y-axis label f"Amplitude ({units})"; x-axis label
     "Probe".

Style both axes through the same `_style_plot_axes`/`apply_theme` path the STDP
dialog uses (theme face/text colours, grid alpha 0.25, integer x locator on the
Search axis). Redraw on every `_update_plot()` and whenever the amplitude-range
spin boxes change (so the deadband/axes track edits before a run), mirroring how
the STDP dialog reconnects `spn_target`/`spn_tolerance.valueChanged`.

A short status label under the plots (like the STDP dialog's
`lbl_relative_difference`) reads e.g. "Rheobase ≈ 2.53 mV (bracket width 0.04)"
or "waiting for first probe".

────────────────────────────────────────────────────────────────────────────────────────────
NOTES
────────────────────────────────────────────────────────────────────────────────────────────

- Spike detection is voltage-threshold crossing in the recorded trace, NOT a
  Brian2 SpikeMonitor. This keeps the routine dependent only on the same
  StateMonitor the STDP routine already needs, and works with imported/replayed
  traces. Reuse `_to_mv` for unit handling; do not re-implement unit parsing.

- The neuron is stimulated through its own stim-array column and observed
  through its own trace row — one `Neuron ID` field drives both. If the stim
  array and the trace enumerate neurons differently in some project, that is the
  user's responsibility (same assumption the STDP routine makes for pre/post IDs).

- Bisection reports `self._high` (the smallest amplitude CONFIRMED to spike) as
  the rheobase, so the reported value always spikes. The bracket is logged so the
  user sees the resolution.

- The 200 ms default recovery lead is deliberately generous. Document in the log
  the first time a probe runs that Vm must rest between probes; if the neuron is
  tonically active (spikes with zero stimulus), probe_min at the minimum amplitude
  will already spike and the routine reports "rheobase <= minimum" — that is the
  correct, honest outcome, not an error.

- Follow the same wheel-guard + scrollable-params + separate-plot-window +
  info-header + Clear-button structure the STDP dialog now has (added in recent
  commits) so the two routines feel identical to use.


────────────────────────────────────────────────────────────────────────────────────────────
NON-GOALS
────────────────────────────────────────────────────────────────────────────────────────────

- STRENGTH–DURATION CURVE (threshold vs. pulse duration). One rheobase for one
  configured pulse duration only. A follow-up routine can sweep durations and
  reuse `count_spikes`.

- f–I / GAIN CURVE beyond threshold. The plot shows spike count at the probed
  amplitudes (which is f–I-like near threshold as a side effect), but the search
  targets the first spike, not the full frequency–current relationship.

- RESETTING neuron state between probes via Brian2 store/restore. The routine
  relies on the recovery lead, consistent with the append-and-run-forward model
  the framework already uses. Do not add checkpoint juggling.

- A SHARED BASE CLASS with InputDesignerDialog. Reuse the two module-level
  helpers (or lift them into `_dialog_helpers.py`); leave the STDP dialog's body
  otherwise untouched.

- CHANGING gui.py. The editor-level callback names are preserved specifically so
  gui.py needs no edits.
