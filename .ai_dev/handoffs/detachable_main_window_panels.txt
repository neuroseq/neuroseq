detachable_main_window_panels — right-click any main-window panel to "Detach
panel" (pop into its own interactive window, hide the original) or "Detach
copy of panel" (same, but the original stays visible too)  [IMPLEMENTED]
================================================================================

GOAL
----
For 7 of the 9 toggleable main-window panels registered in `Gui._view_actions`
(`gui.py:2803-2837`) — Traces, Spikes, Data, Heatmap, Spatial Footprints,
Custom Analysis, Console, Chat — add two right-click context-menu actions:

  1. "Detach panel" — construct a fresh, fully-functional instance of that
     panel showing its CURRENT data, place it in its own top-level window
     (interactive, scrollable, all the panel's normal functionality intact),
     and hide the original (via its existing View-menu toggle action, so it
     can be re-shown the normal way later).
  2. "Detach copy of panel" — identical, except the original stays visible.

**Stimuli is explicitly OUT OF SCOPE.** `StimEditor`'s widget is entangled
with a combo box (`cmb_stim`, living in the main toolbar) and a toolbar
(`toolbar_stim_editor`, added directly to `main_horizontal_layout`, not part
of either splitter) that live in *separate* parts of the main window —
detaching the panel alone would strand its selection/actions. Do not add
detach actions to `StimWidget`'s context menu (see the guard in the
TimeseriesWidget section below); this is a deliberate exclusion, not an
oversight, and a follow-up item for later.

DESIGN — read this before writing any code
--------------------------------------------
**Mechanism: construct-fresh, never reparent.** Both actions build a BRAND
NEW instance of the panel's widget class (never `setParent()` the live,
already-displayed widget into a new window). This is the ONLY existing
precedent in the codebase — `CustomAnalysisWindow` (`custom_analysis_widget.py:39-57`)
already does exactly this for the Custom Analysis panel, via
`Gui._custom_analysis` (`gui.py:578-601`) — and it sidesteps a real risk:
these panels are `fastplotlib`/WGPU-backed (`FPLWidget` base,
`fpl_widget.py:18-83`), whose GPU canvas surface is bound to a native window
handle; reparenting a LIVE canvas across top-level windows is untested in
this codebase (it has defensive "canvas isn't ready yet" guard code —
`_fpl_canvas_ready`/`_fpl_guarded_render`, `fpl_widget.py:62-83` — for even
routine viewport-size-zero situations at startup) and would likely need new,
unproven guard logic. Constructing a fresh instance means each detached copy
owns its own independent `fpl.Figure`/GPU device (confirmed: no panel
instance shares a `Figure` with another today), so nothing about closing one
copy risks another.

**"Detach" and "Detach copy" are the SAME mechanism** — the only difference
is whether the original panel's View-menu toggle action gets unchecked
afterward. Implement them as one internal method with a `keep_original: bool`
parameter, called from two thin action handlers.

**Scope of "current data"**: a detached/copied instance is seeded with
whatever is CURRENTLY displayed, and remains fully interactive from then on
(pan/zoom, right-click-analyze, cell-click-to-grey, its own scrollbars/REPL/
chat input — whatever that panel type normally supports). It does **not**
need to keep tracking later, unrelated changes elsewhere in the main window
(e.g. the user picking a different trace in `cmb_trace` after the detach) —
this matches the one existing precedent (`CustomAnalysisWindow` also just
seeds-and-forgets) and keeps this from becoming a much larger "live-mirror
every combo-box change to every detached copy" project.

**Seed data from the canonical source (`Project`/comboboxes), never from the
widget's own stored state** — several widgets don't retain what they were
given in a form usable for re-seeding:
  - `HeatmapWidget.set_data(data: SynapseData)` stores `self.data =
    data.values.T` (a transformed ndarray, NOT the original `SynapseData` —
    `heatmap_widget.py:196-209`). Re-fetch via
    `self.project.get_data(self.cmb_synapse.currentText(), SynapseData)`
    instead (the same call `Gui` itself already makes, e.g. `gui.py:1297-1298`).
  - `CustomAnalysisWidget.set_data(data, analysis_type, neuron_slice,
    time_slice)` stores none of its four arguments — only derived
    `self.traces`/`self.spike_indices`/etc. (`custom_analysis_widget.py:122-183`).
    There is currently NO way to recover "what's shown right now" from
    `self.custom_analysis_widget`. Fix: have `Gui._custom_analysis`
    (`gui.py:578-601`) also stash the four arguments whenever `new_window` is
    False (i.e. whenever the DOCKED panel is what got updated):
    `self._last_custom_analysis = (data, analysis_type, neuron_slice,
    time_slice)` (add this attribute, `None` initially, in `Gui.__init__`).
    The Custom Analysis panel's own detach factory reads from
    `self._last_custom_analysis`; if it's still `None` (nothing analyzed
    there yet), show a `QMessageBox.information` ("Nothing to detach yet")
    instead of opening an empty window.
  - `TraceWidget`/`SpikeWidget` DO retain usable state on `self.data`
    (`timeseries_widget.py:100`, set verbatim in `set_data`,
    `trace_widget.py:218-231` / `spike_widget.py:34-40`) — but prefer
    `self.project.get_data(self.cmb_trace.currentText(), TraceData)` /
    `..., SpikeData)` anyway, for consistency with how `Gui` already re-derives
    this data everywhere else (e.g. `gui.py:1286-1288,1289-1292`).
  - `SpatialFootprintWidget._cellpose_data` (private, `spatial_footprint_widget.py:55-56`)
    IS the same object as `self.project.cellpose_data` — either works; use
    `self.project.cellpose_data` for consistency.
  - `ConsoleWidget`/`ChatWidget` are genuinely stateful (REPL transcript/
    history, chat message log) — see their own sections below.

**Controllers**: `Gui.__init__` builds three separate `ConstrainedPanZoomController()`
instances (`gui.py:344-346`): `self.controller` (used only as the optional
`default_controller` for the "lock to default view" checkbox — NOT a live
pan/zoom sync mechanism), `self.trace_controller` (Traces' own primary
camera controller), `self.spike_controller` (Spikes' own). No panel shares a
live primary controller with another. A detached Traces/Spikes/Data instance
needs its OWN fresh `ConstrainedPanZoomController()` (takes no required args,
`constrained_pan_zoom_controller.py:30-47`) as its primary controller, and
may reuse `self.controller` as `default_controller` (safe — it only affects
optional axis-locking, not automatic sync). `HeatmapWidget`/`SpatialFootprintWidget`
take no controller argument at all (`heatmap_widget.py:87`,
`spatial_footprint_widget.py:21`) — nothing to wire.

**Signal reconnection**: for each panel type, grep `gui.py`'s `Gui.__init__`
for every `self.<panel_attr>.<signal>.connect(...)` call and reproduce EVERY
one of them on the fresh instance, connected to the identical bound `Gui`
method. Do not assume the lists below are exhaustive — re-grep and confirm
before writing each factory. Known ones from this investigation:

    (`gui.py:355-357`); `neuron_greyed_out_changed` → `Gui._on_neuron_greyed_out_changed`
    (`gui.py:358-360`).
  - `TraceWidget`/`SpikeWidget.custom_analysis_requested` → `Gui._custom_analysis`
    (connections around `gui.py:471,475,478,479` — re-grep to confirm exact
    lines and whether both widgets connect to the same handler).
  - `ConsoleWidget.console_command_entered` → `Gui._update_data` (`gui.py:462`);

NEW FILE — src/neuroseq/detached_panel_window.py

One generic, reusable wrapper for every detached panel (mirrors
`CustomAnalysisWindow`'s shape, but generic over the embedded widget and
scrollable per the explicit "still... scrollable" requirement — reuse the
`QScrollArea` pattern `tif_import_dialog.py` already established for a
similar "content might not fit the window" concern, `tif_import_dialog.py:260-266`):

    from __future__ import annotations

    from collections.abc import Callable

    from qtpy import QtCore
    from qtpy import QtWidgets


    class DetachedPanelWindow(QtWidgets.QWidget):
        """Top-level window wrapping one detached (freshly-built) panel instance."""

        def __init__(
            self,
            widget: QtWidgets.QWidget,
            title: str,
            *,
            on_close: Callable[[], None] | None = None,
            parent: QtWidgets.QWidget | None = None,
        ) -> None:
            super().__init__(parent)
            self.setAttribute(QtCore.Qt.WidgetAttribute.WA_DeleteOnClose)
            self.setWindowFlags(
                QtCore.Qt.WindowType.Window | QtCore.Qt.WindowType.Tool
            )
            self.setWindowTitle(title)
            self.resize(800, 600)
            self._widget = widget
            self._on_close = on_close

            layout = QtWidgets.QVBoxLayout(self)
            layout.setContentsMargins(0, 0, 0, 0)
            scroll_area = QtWidgets.QScrollArea(self)
            scroll_area.setWidgetResizable(True)
            scroll_area.setWidget(widget)
            layout.addWidget(scroll_area)

        def closeEvent(self, event: QtCore.QEvent) -> None:
            # Fastplotlib-backed widgets need their renderer explicitly
            # stopped before Qt destroys them (see FPLWidget.closeEvent,
            # DataWidget.closeEvent, Gui.closeEvent for the same idiom) —
            # widgets without a meaningful close() (ConsoleWidget, ChatWidget)
            # just get the default QWidget.close(), which is a no-op beyond
            # hiding, so calling it unconditionally here is always safe.
            self._widget.close()
            if self._on_close is not None:
                self._on_close()
            super().closeEvent(event)

`setWidgetResizable(True)` is required — without it `QScrollArea` won't
let the embedded widget grow to fill the window, defeating the point of a
resizable detached window that's ALSO scrollable when made smaller than the
content's natural size.

       def _panel_title(self, widget: QtWidgets.QWidget) -> str:
           action = self._view_actions.get(widget)
           if action is None:
               return "Panel"
           # action.text() is like "Show &Traces" / "Hide &Traces" — strip the
           # leading verb and the mnemonic ampersand for a clean window title.
           return action.text().split(" ", 1)[-1].replace("&", "")

       def _build_detached_widget(
           self, source: QtWidgets.QWidget
       ) -> QtWidgets.QWidget | None:
           """Construct a fresh, fully-wired instance mirroring `source`'s
           current data. Returns None if there is nothing to show yet
           (e.g. Custom Analysis before anything has been analyzed)."""
           if source is self.trace_widget:
               return self._build_fresh_trace_widget()
           if source is self.spike_widget:
               return self._build_fresh_spike_widget()
           if source is self.data_widget:
               return self._build_fresh_data_widget()
           if source is self.heatmap_widget:
               return self._build_fresh_heatmap_widget()
           if source is self.spatial_footprint_widget:
               return self._build_fresh_spatial_footprint_widget()
           if source is self.custom_analysis_widget:
               return self._build_fresh_custom_analysis_widget()
           if source is self.console_widget:
               return self._build_fresh_console_widget()
           if source is self.chat_widget:
               return self._build_fresh_chat_widget()
           return None

       def detach_panel(self, source: QtWidgets.QWidget, *, keep_original: bool) -> None:
           widget = self._build_detached_widget(source)
           if widget is None:
               QtWidgets.QMessageBox.information(
                   self, "Nothing to detach", "This panel has nothing to show yet."
               )
               return
           window = DetachedPanelWindow(
               widget, self._panel_title(source), parent=self
           )
           window.show()
           if not keep_original:
               action = self._view_actions.get(source)
               if action is not None:
                   action.setChecked(False)  # goes through _set_widget_visible

   Each `_build_fresh_*_widget` is a small private method — see per-panel
