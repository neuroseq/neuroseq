syscon2_exporter_fixed_timeline_layout — Match SysCon v3 absolute timeline/lightsource layout [IMPLEMENTED]
============================================================================================================

The SysCon2 exporter currently writes laser TTLPulse objects onto **dynamic** timeline
indices computed as `n_entity_lanes + offset`, with a wavelength→offset map and a
wavelength→lightsource_id map that don't match what SysCon v3 actually expects. As a
result, exported `.seq` files load into SysCon but the laser TTL pulses arrive on the
wrong lane (e.g. on a TTL-out row, or on a different wavelength's row), and the
lightsource named on the pulse doesn't match the lane.

Three reference `.seq` files from the up-to-date SysCon software (each contains one
Shape + one laser TTL + TTL Out 1 + TTL Out 2) establish the true layout:

  ~/Downloads/laser_1100nm_TL2.seq
  ~/Downloads/laser_940nm_TL3.seq
  ~/Downloads/laser_1030nm_TL4.seq

(The filename "TLn" is the 1-based SysCon UI row; the on-disk `TimelineInfo0_TimelineIndex`
value is `n-1`. So "TL2" == TimelineIndex 1.)

This handoff swaps the exporter to **absolute, fixed** timeline indices, fixes the
wavelength↔lightsource_id mapping, fixes the wavelength label (1140 → 1100, with 1140
kept as a legacy alias mirroring the existing 1040→1030 alias), and forces the Shape's
LightsourceID to the SLM-driver value the references all use.

Single file to change:
    src/neuroseq/exporter_syscon2.py

Tests to update (golden indices baked in):
    tests/test_exporter_syscon2.py

UI label to update:
    src/neuroseq/stimulation_generator_dialog.py (one combo-box line)

────────────────────────────────────────────────────────────────────────────────────────────
BACKGROUND — what the reference files prove
────────────────────────────────────────────────────────────────────────────────────────────

Across all three reference files, the layout is identical except for the active
wavelength's TTLPulse row and its LightsourceID/port:

  TimelineIndex  Purpose              LightsourceID  port
  0              Shape (SLM)          dummy_2_0      (no port; Intensity_0=0)
  1              Laser TTL @ 1100 nm  dummy_2_0      dummy_2_0 RMI In
  2              Laser TTL @ 940  nm  dummy_1_0      dummy_1_0 RMI In
  3              Laser TTL @ 1030 nm  dummy_0_0      dummy_0_0 RMI In
  4              TTL Out 1 (mirror)   —              Holo4D TTL Out 1
  5              TTL Out 2 (gate)     —              Holo4D TTL Out 2

Key observations:

  (a) Timeline indices for lanes 1..5 are **absolute and fixed** — they do NOT depend on
      how many shape lanes a particular stim needs. This is the primary bug: today's code
      writes `laser_timeline_index = n_entity_lanes + offset` (exporter_syscon2.py:577-581),
      so when a stim uses 2+ shape lanes, the laser pulses spill onto rows 4/5/6 — which
      SysCon shows as TTL-out / wrong-wavelength rows.

  (b) The row↔lightsource_id binding is 1:1 in SysCon: row 1 always carries dummy_2_0,
      row 2 always dummy_1_0, row 3 always dummy_0_0. Our current
      `_LIGHTSOURCE_ID_BY_WAVELENGTH_NM` (exporter_syscon2.py:51-55) has 940 and 1030
      **swapped** vs. the references.

  (c) The Shape's `Intensity_0 = 0` in every reference file, with LightsourceID
      `dummy_2_0` regardless of which laser TTL fires. So the Shape's lightsource is a
      SLM-driver constant, NOT the active laser. We should emit `dummy_2_0` on every
      Shape and ignore the active wavelength when picking that field.

  (d) TTL Out 1 mirrors the laser TTL exactly: same `starttime`, same `repeats`
      (16 ticks in every reference). This is the "spiraling trigger" the user described.
      Our current code already emits this — but on the wrong absolute lane
      (`n_entity_lanes + 3` instead of fixed 4). The mirroring itself is correct.

  (e) TTL Out 2 is present in every reference and pre/post-pads the active stim window
      (e.g. starts at tick 26 = 13541.125 µs; ends 22+ ticks past shape end). The exact
      timing varies across the three reference files (repeats=123/140/123) — likely
      because the user hand-tuned it per file. The exporter currently does NOT emit
      TTL Out 2 (see comment at exporter_syscon2.py:582). **TTL Out 2 is OUT OF SCOPE
      for this patch** — leaving the current "TTL Out 2 unused" behaviour as-is. A
      follow-up patch can add it once the user specifies a deterministic timing rule
      (e.g. "start at first-shape - N ticks, end at last-laser-TTL + M ticks").

  (f) The wavelength label "1140" used throughout NeuroSeq is what SysCon and the
      Rapp LUT file (`20260526_1100-LUT_RAPP.lut`) call "1100". Same physical lightsource
      (`dummy_2_0`). Rename the canonical value to 1100 and keep 1140 as a legacy alias
      (same shape as the existing `_LEGACY_LASER_WAVELENGTH_ALIASES_NM = {1040: 1030}`).

────────────────────────────────────────────────────────────────────────────────────────────
OPEN QUESTION — multi-shape-lane layout
────────────────────────────────────────────────────────────────────────────────────────────

The reference files all have exactly one shape, on TimelineIndex 0. The current
exporter supports stims that need multiple simultaneous shape lanes (controlled by
`_max_simultaneous_entity_windows` at exporter_syscon2.py:1305 and `_assign_entity_lanes`
at 3309). With the new fixed layout, indices 1..5 are reserved — so additional shape
lanes cannot live at 1/2/3/4/5.

**Decision adopted in this patch:** shape lanes use the contiguous index set
`{0, 6, 7, 8, ...}`, i.e. lane 0 stays on row 0 and any additional lanes go to row 6 and
above. This preserves the convention shown in every reference, and "pushes" extra shape
lanes safely past the reserved rows. If the user later confirms a different convention,
this is a one-line constant change.

In code: when `_assign_entity_lanes` returns a lane index `i`, map it to a
TimelineIndex via `_shape_lane_to_timeline_index(i)`:

    def _shape_lane_to_timeline_index(lane: int) -> int:
        # Lane 0 → row 0; lanes 1..N → rows 6, 7, 8, …
        # Rows 1..5 are reserved for lasers (1..3) and TTL outs (4..5).
        return 0 if lane == 0 else lane + 5

(If the user later confirms that all shape lanes should go above the reserved block,
change this to `return lane + 6`. Add a `# TODO confirm with hardware owner` if helpful.)

OUT OF SCOPE — explicitly NOT in this patch
────────────────────────────────────────────────────────────────────────────────────────────

  - Emitting TTL Out 2 objects. The references show TTL Out 2 envelopes the stim, but
    the timing (start/end ticks) varies between reference files and we don't have a
    deterministic rule from the user. Leave the current "TTL Out 2 unused" behaviour
    as-is. The `ttl_out2_timeline_index` field on `SysconExportReport` stays — it just
    points at the (correct) reserved row 5 now.

  - Integrating the Rapp LUT (`20260526_1100-LUT_RAPP.lut`) for intensity → mW power
    calibration. Not part of the `.seq` exporter; LUT is loaded by SysCon directly.

  - Changing the template's `SourceConnectorPort1=dummy_2_0 RMI In` /
    `TargetConnectorPort1=Holo4D TTL Out 2` lines — those come from the user's
    template, and `_build_header_lines` already strips/normalises them. Leave alone.

  - Reworking `_max_simultaneous_entity_windows` / `_assign_entity_lanes`. The lane
    *assignment* algorithm is unchanged — only the lane→timeline-index mapping changes,
    via the new helper at the export boundary.
