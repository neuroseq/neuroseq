spatial_footprint_viewer — Toggleable main-window viewer for cell spatial footprints, with click-to-grey linking to the trace/stim rows [IMPLEMENTED]
=======================================================================================================================================================

Add a new dockable panel to the main window, toggled from the top bar exactly
like the existing "Heatmap" (Synapses) panel: a checkable toolbar/menu action
that shows/hides a widget living in the same splitter as `heatmap_widget`.
The panel shows the imported Cellpose segmentation (colour-coded cells with
ID labels — the same "Color-coded Preview" already used in the Cellpose
import dialog) for the CURRENT project's `Project.cellpose_data`. Clicking a
cell toggles a persistent grey overlay on that cell in the picture AND on the
corresponding row in both `trace_widget` and `stim_editor.stim_widget`.
Clicking the same cell again removes all three grey overlays.

There is no new cell-segmentation code to write: `Project.cellpose_data`
(`CellposeImportResult`) already carries a ready-to-display
`overlay_image` + `segmentation_array`, and `CellOverlayWidget` (used today
only inside the Cellpose import dialog) already renders exactly this
image with colour-coded, ID-labelled cells via `neuron_indices_to_colors` —
the SAME colour function `TraceWidget` uses for its lines
(`neuron_indices_to_colors`, `utils.py:111`), so cell colours in the new
panel will already visually match trace colours. Reuse it.

Neuron-index conventions (confirmed by reading the code, not assumed):

- `TraceData.indices[i]` and a `StimArray`'s column index `j` are the SAME
  integer space as `CellposeImportResult.stimulus_to_cellpose_mapping`'s KEY
  (`stim_id`). See `importer_suite2p.py:97-138`
  (`_resolve_suite2p_indices`): it builds the Suite2p `TraceData.indices`
  array by inverting `stimulus_to_cellpose_mapping` (`stim_id -> cellpose_id`
  becomes `cellpose_id -> stim_id`), falling back to `cellpose_id` itself
  when a cellpose id has no explicit entry (identity mapping). Use the exact
  same inversion + fallback for the new widget:

        cellpose_to_stim = {v: k for k, v in (mapping or {}).items()}
        stim_id = cellpose_to_stim.get(cellpose_id, cellpose_id)

- In `TraceWidget`/`StimWidget` (both extend `TimeseriesWidget`), neuron `i`
  occupies the world-space row `y ∈ [i - 0.5, i + 0.5]`, full time width.
  This is the same convention `TimeseriesWidget.pointer_move`'s SELECT mode
  already uses to build `neuron_slice` from a mouse position
  (`timeseries_widget.py:610-619`), and it's what `RegionOfInterest.select_slice`
  already draws (`region_of_interest.py:39-62`). Reuse `RegionOfInterest` for
  the grey overlay rather than inventing a new graphic type.

- `CellOverlayWidget.set_overlay(overlay_image, segmentation, original_cellpose_ids,
  stimulus_to_cellpose_mapping, legend_data=None, ...)` already renders
  everything needed: pass `legend_data=None` and it auto-computes colours via
  `neuron_indices_to_colors` (`cell_overlay_widget.py:1139-1154`,
  `_compute_segementation_colors`). `self.segmentation` inside `OverlayView`
  is ALWAYS keyed by raw Cellpose ID regardless of the `show_stimulus_ids`
  display toggle (`cell_overlay_widget.py:1011`,
  `label_segmentation=self.segmentation` is passed separately from the
  possibly-remapped `display_segmentation`) — so pixel lookups into
  `OverlayView.segmentation` always give you a Cellpose ID, which is what you
  invert to a stim_id via the mapping above.

- Hit-testing a pixel under the pointer already has a working precedent in
  `OverlayView.pointer_move` (`cell_overlay_widget.py:869-891`):

        x = int(mouse_pos[0])
        y = int(mouse_pos[1])
        # bounds-check against self.segmentation.shape
        neuron_index = self.segmentation[y, x]   # -1 == background

  `mouse_pos` comes from `self.subplot.map_screen_to_world(ev)`. Use the
  exact same formula for the new click handler — no y-flip/user-coord
  conversion needed here (that conversion is only for the AOI *shapes*,
  which are stored in "user" pixel coordinates; the segmentation ARRAY
  lookup already works directly on world coords as shown above).

- `CellposeImportResult.segmentation_array` and `.overlay_image` are
  non-optional dataclass fields — whenever `Project.cellpose_data is not
  None`, both are present (`importer_cellpose.py:50-62`).

            if not self.enable_cell_selection or self._cell_click_down_world is None:
                return
            down_x, down_y = self._cell_click_down_world

NEW FILE — src/neuroseq/spatial_footprint_widget.py
────────────────────────────────────────────────────────────────────────────────────────────

A thin widget that owns a `CellOverlayWidget`, knows about
`CellposeImportResult` and the stim_id/cellpose_id mapping, and turns clicks
into a `(stim_id, greyed)` signal. It does NOT know about `TraceWidget` or
`StimWidget` — gui.py is the only thing that connects the two sides.

    from __future__ import annotations

    import brian2.numpy_ as np
    from qtpy import QtCore
    from qtpy import QtWidgets

    from neuroseq.cell_overlay_widget import CellOverlayWidget
    from neuroseq.cell_overlay_widget import compute_segmentation_legend
    from neuroseq.importer_cellpose import CellposeImportResult

    GREY_RGB_255 = (140, 140, 140)


    class SpatialFootprintWidget(QtWidgets.QWidget):
        """Shows the imported cell spatial footprints; clicking a cell toggles
        a grey-out state that gui.py mirrors onto the trace/stim rows."""

        # emits (stim_id, greyed) — stim_id is the same neuron-index space used
        # by TraceData.indices / StimArray columns, NOT the raw Cellpose id.
        neuron_greyed_out_changed = QtCore.Signal(int, bool)

        def __init__(self, parent: QtWidgets.QWidget | None = None) -> None:
            super().__init__(parent)
            layout = QtWidgets.QVBoxLayout(self)
            layout.setContentsMargins(0, 0, 0, 0)
            self.overlay_widget = CellOverlayWidget(title="Spatial Footprints")
            self.overlay_widget.set_display_options(
                show_cellpose_ids=False, show_stimulus_ids=True
            )
            self.overlay_widget.set_cell_selection_enabled(True)
            self.overlay_widget.neuron_clicked.connect(self._on_neuron_clicked)
            layout.addWidget(self.overlay_widget)
            self._cellpose_data: CellposeImportResult | None = None
            self._base_legend: list[tuple[int, tuple[int, int, int]]] = []
            self._greyed_cellpose_ids: set[int] = set()

        def set_data(self, cellpose_data: CellposeImportResult | None) -> None:
            self._cellpose_data = cellpose_data
            self._greyed_cellpose_ids = set()
            if cellpose_data is None:
                self._base_legend = []
                self.overlay_widget.set_empty_message(
                    "No cell spatial footprints loaded."
                )
                return
            self._base_legend = compute_segmentation_legend(
                cellpose_data.segmentation_array
            )
            self._refresh_overlay()

        def _refresh_overlay(self) -> None:
            if self._cellpose_data is None:
                return
            legend = [
                (cell_id, GREY_RGB_255 if cell_id in self._greyed_cellpose_ids else rgb)
                for cell_id, rgb in self._base_legend
            ]
            self.overlay_widget.set_overlay(
                self._cellpose_data.overlay_image,
                self._cellpose_data.segmentation_array,
                self._cellpose_data.original_cellpose_ids,
                self._cellpose_data.stimulus_to_cellpose_mapping,
                legend_data=legend,
            )

        def _cellpose_to_stim_id(self, cellpose_id: int) -> int:
            mapping = (
                self._cellpose_data.stimulus_to_cellpose_mapping
                if self._cellpose_data is not None
                else None
            )
            cellpose_to_stim = {v: k for k, v in (mapping or {}).items()}
            return cellpose_to_stim.get(cellpose_id, cellpose_id)

        def _on_neuron_clicked(self, cellpose_id: int) -> None:
            if cellpose_id in self._greyed_cellpose_ids:
                self._greyed_cellpose_ids.discard(cellpose_id)
                greyed = False
            else:
                self._greyed_cellpose_ids.add(cellpose_id)
                greyed = True
            self._refresh_overlay()
            self.neuron_greyed_out_changed.emit(
                self._cellpose_to_stim_id(cellpose_id), greyed
            )

        def close(self) -> bool:
            self.overlay_widget.close()
            return super().close()

   Notes on the sketch above:
   - `set_overlay(...)` is called with an explicit `legend_data` (not `None`)
     every time so that a previously-computed colour assignment survives
     toggling — recomputing from scratch via `_compute_segementation_colors`
     inside `CellOverlayWidget` would still be *consistent* (same inputs,
     same colours) but doing it once in `set_data` and reusing it is cheaper
     and makes the "only the clicked cell's colour changes" behaviour
     explicit and easy to test.
   - Greying only recolours the cell's overlay region, not its ID label text
     (`OverlayView._update_label_graphics` has substantial existing logic
     around highlighting/crossing-out labels for remapped ids — leave it
     untouched; see NON-GOALS).

NOTES
────────────────────────────────────────────────────────────────────────────────────────────

- Colour consistency is automatic, not something to engineer: both
  `TraceWidget` (`neuron_indices_to_colors(self.data.indices)`,
  `trace_widget.py:196`) and `compute_segmentation_legend` (extracted from
  `CellOverlayWidget`) call the same `neuron_indices_to_colors` on the same
  kind of zero-based index array. As long as the segmentation's cell ids,
  once zero-based, line up with a neuron's `stim_id` (true whenever the
  Cellpose import didn't need a custom remapping — the common case), the
  cell's colour in the new panel and its trace's colour will already match
  without any extra code. When a custom/AOI remapping IS in effect, colours
  will diverge between the two views (the segmentation legend colours by
  Cellpose id, not stim_id) — that's a pre-existing property of
  `CellOverlayWidget` today (see `_get_display_legend`'s remapping branch)
  and out of scope to change here.

- `StimWidget.set_neuron_greyed` and `TraceWidget.set_neuron_greyed` are the
  exact same inherited method — no per-widget override needed. Sanity-check
  after implementing that the grey rectangle actually renders on top of the
  stim image (z=250 vs. `StimWidget.STIMULUS_Z=200`/`MINIMUM_SIZE_Z=210`) and
  underneath the hover crosshair/axes (z=300) — check by eye with
  `uv run neuroseq` and a project that has both stim data and cellpose data
  loaded, clicking a cell and confirming both rows visibly grey out.

- The grey overlay spans the FULL time width of the widget's data
  (`0` to `n_timestamps * dt_ms`, or the controller's `max_width` if data
  hasn't loaded yet), not just the currently-visible/zoomed time range — so
  panning/zooming the trace or stim view horizontally keeps the neuron
  greyed the whole time, which matches "this neuron is excluded" semantics
  better than a viewport-relative overlay would.

- `RegionOfInterest.select(x0, x1, y0, y1)` takes world coordinates directly;
  double-check the sign/order convention against how `self.roi.select_slice`
  already calls it (`region_of_interest.py:57-62`) if the rendered rectangle
  ends up in the wrong place — `y0 = neuron_index - 0.5` should end up as
  the BOTTOM edge of the row, matching the ROI-selection convention exactly.


────────────────────────────────────────────────────────────────────────────────────────────
NON-GOALS
────────────────────────────────────────────────────────────────────────────────────────────

- SYNCHRONISING greyed state across a dataset switch. If the user greys
  neuron 5, then picks a different entry in `cmb_trace`, `TraceWidget.clear_data()`
  drops that neuron's overlay (same as it already drops the unrelated ROI
  selection state today). The Spatial Footprints panel's own greyed set is
  untouched by this — clicking the same cell again still works correctly
  (idempotent `set_neuron_greyed` re-applies the correct state), but the
  trace/stim panels won't "remember" the grey mark across a dataset switch
  without a fresh click. Wiring re-application into every `set_data()` call
  site in gui.py (`_apply_trace_selection`, `_rewindow_simulation_views`,
  etc.) is explicitly out of scope.
- GREYING the ID label text in the segmentation picture itself (only the
  cell's coloured region is recoloured to grey).
- MULTI-SELECT gestures (shift-click ranges, drag-select multiple cells,
  "grey all" / "clear all" buttons). One click toggles one cell.
- Any interaction with `AreasOfInterestConfig`/AOI shapes. The new panel
  never sets `_aoi_config`, so no AOI shapes are ever drawn in it.
- Persisting the greyed set into the `.nseq` project file. It's view-only
  interaction state that resets when the project reloads or the app
  restarts (consistent with the existing ROI-selection state, which also
  isn't persisted).
- A combo box / multi-dataset picker for the spatial footprint panel.
  `Project.cellpose_data` is a single optional slot, not a named collection
  like `TraceData`/`SpikeData`/`SynapseData`.
