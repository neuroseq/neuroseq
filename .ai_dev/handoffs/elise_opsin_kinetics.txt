elise_opsin_kinetics — 3-state PyRho-collapsed opsin kinetics for ELISE
========================================================================

Replace the current "stim _is_ the conductance" coupling between
`opsin_exc`/`opsin_inh` and ELISE's matching potential with a 3-state
kinetic layer (closed / open / desensitized) driven by photon flux.
Re-interpret the two opsin stim arrays as **photon flux density**
(mm⁻²·s⁻¹) instead of fractional conductance. Re-derive the Für-Elise
defaults via the steady-state Hill so the macroscopic teaching signal
(`u_tgt ≈ -50 mV` for active pitches, `≈ -70 mV` for rest pitches) is
preserved within sub-percent error. Add archive migration so existing
`.nseq` files keep working.

Authoritative spec: `.ai_dev/specs/elise_opsin_kinetics.md` — read it
first. This handoff sequences the work, flags places where the spec
disagrees with the current codebase, and prescribes the test surface.

────────────────────────────────────────────────────────────────────────────────────────────
SPEC DEVIATIONS — read these before implementing
────────────────────────────────────────────────────────────────────────────────────────────

1.  `Elise._signature` IS NOT A METHOD. The spec shows a
    `def _signature(self) -> tuple` returning a tuple of kinetic
    fields. In the actual code (elise.py:452-459) the signature is
    constructed inline in `simulate()` as:

        signature = (
            num_vis,
            tuple(
                sorted(
                    (k, v) for k, v in self._params.items()
                    if k not in self._PHASE_PARAMS
                )
            ),
        )

    This already covers any new `DEFAULT_PARAMS` keys automatically.
    So adding the kinetic parameters to `DEFAULT_PARAMS` is sufficient
    to invalidate the network cache when they change. **Do not add a
    new `_signature` method.** The "extend `_signature`" instruction
    in the spec is a no-op for the current code shape.

2.  ELISE's default `dt_ms` is **0.1 ms**, not 1 ms. The spec's
    stability claim ("forward Euler is stable at `dt = 1 ms` because
    the fastest active rate is `k_a_max = 1000 s⁻¹`") is even more
    comfortably true at the actual default — `k_a_max * dt = 0.1`,
    far below the Euler stability threshold. Use forward Euler
    unconditionally; do NOT add the `if k_a_max * dt > 0.5` guard the
    spec mentions. It can be added later if a user pushes `k_a_max`
    high enough to matter.

3.  `simulate()` per-step `dt` IS `dt_ms / 1000.0` (seconds), not
    `dt_ms`. Use seconds in the kinetic step so the rate-constants
    (s⁻¹) and `dt` units match cleanly.

4.  Numba is NOT a current NeuroSeq dependency (`uv pip install` does
    not pull it in; `import numba` fails). The spec shows
    `@njit(cache=True, fastmath=False)` decorating `_step_kinetics`.
    With `num_vis ≈ 13` in the Für-Elise project, a pure-numpy
    vectorised kinetic step costs ~5 µs per call — utterly negligible
    next to the ELISE forward pass. **Implement `_step_kinetics` as
    pure numpy.** Do not add `numba` to `pyproject.toml` for this.
    Vectorised form below.

5.  The current `Elise` class has `_PHASE_PARAMS = frozenset({"learn"})`.
    Kinetic parameters are NOT phase params. Don't touch
    `_PHASE_PARAMS` — leave it alone. New params land in the
    "trajectory" partition automatically (via `update_params`,
    elise.py:360-365), which calls `reset()` when they change.
    That's the desired behaviour: changing `k_a_max_exc` between
    runs DOES discard the network state and zero the kinetic state
    arrays. Confirmed by `test_kinetic_signature_includes_kinetic_params`.

6.  The spec mentions `Elise._ensure_network()`. The actual method is
    `_initialize_network(num_vis)` (elise.py:389). Allocate state
    arrays there.

7.  `StimArray.units` for the opsin pair in `elise_project()` is
    currently the literal string `"1"` (example_projects.py:1613,
    1622). Change to `"mm^-2 s^-1"`. Units are display-only metadata;
    the simulator reads `.values` directly.

8.  The spec talks about a "deeper opsin layer" stored on `self._params`
    namespace (`self._params.k_a_max_exc`). The actual ELISE code reads
    parameters via `_float_param(self._params, "k_a_max_exc")` — flat
    dict access by string key, not attribute. Adapt all the code
    snippets in the spec accordingly.

Add at module scope, near the existing `_build_namespaces` helper:

    def _step_kinetics(
        O: np.ndarray,
        D: np.ndarray,
        phi: np.ndarray,
        k_a_max: float,
        phi_m: float,
        k_d: float,
        k_r: float,
        dt: float,
    ) -> None:
        """Vectorised forward-Euler step on the 3-state opsin kinetics.

        Mutates `O` and `D` in place. `C = 1 - O - D` is reconstructed
        per step. Hill activation with exponent 1 — `phi = 0` gives
        `k_a = 0` cleanly (no NaN), so no explicit Theta gate is
        needed.

        All arrays have shape `(num_vis,)` and dtype float64. `dt` is
        in seconds; rates are in s^-1.
        """
        k_a = k_a_max * phi / (phi + phi_m)
        C = 1.0 - O - D
        dO = (k_a * C - k_d * O) * dt
        dD = (k_d * O - k_r * D) * dt
        O += dO
        D += dD

`phi + phi_m` cannot be zero (phi_m > 0), so no divide-by-zero. The
formula `0/(0+phi_m) = 0` covers the dark case without branching.

    def _calibrate_phi_for_target_open_fraction(
        O_target: float,
        k_a_max: float,
        phi_m: float,
        k_d: float,
        k_r: float,
    ) -> float:
        """Inverse Hill — return φ such that O*(φ) = O_target.

        The steady-state open fraction for the 3-state model is:
            O* = k_a · k_r / (k_a · k_r + k_a · k_d + k_d · k_r)
        Solving for k_a:
            k_a = O_target · k_d · k_r / (k_r · (1 - O_target) - k_d · O_target)
        And inverting the Hill `k_a = k_a_max · φ / (φ + phi_m)`:
            φ = k_a · phi_m / (k_a_max - k_a)
        """
        if O_target <= 0:
            return 0.0
        denom = k_r * (1.0 - O_target) - k_d * O_target
        if denom <= 0:
            raise ValueError(
                f"O_target={O_target} exceeds physical maximum "
                f"for k_d={k_d}, k_r={k_r} (denominator <= 0)."
            )
        k_a = O_target * k_d * k_r / denom
        if k_a >= k_a_max:
            raise ValueError(
                f"O_target={O_target} exceeds k_a_max={k_a_max} "
                f"saturation limit (need k_a={k_a:.3e})."
            )
        return k_a * phi_m / (k_a_max - k_a)

    # neuroseq.example_models.elise). Kept as literals here so the
    # photon-flux constants below stay stable across Elise refactors
    # — if the user retunes opsin kinetics in the model editor, the
    # Für-Elise stim values won't silently shift under them.
    _ELISE_KIN_EXC = dict(k_a_max=1000.0, phi_m=5e17, k_d=50.0, k_r=5.0)
    _ELISE_KIN_INH = dict(k_a_max=800.0,  phi_m=5e17, k_d=10.0, k_r=5.0)

    _O_SAT_EXC = (
        _ELISE_KIN_EXC["k_a_max"] * _ELISE_KIN_EXC["k_r"]

        + _ELISE_KIN_EXC["k_a_max"] * _ELISE_KIN_EXC["k_d"]

    _g0_ratio = 0.5 * _O_SAT_EXC / _O_SAT_INH    # g0_inh / g0_exc

    _FUER_ELISE_PHI_EXC_ACTIVE = 100.0 * _ELISE_KIN_EXC["phi_m"]
    _FUER_ELISE_PHI_INH_ACTIVE = 100.0 * _ELISE_KIN_INH["phi_m"]

    # Rest = photon flux that yields the matching-potential ratio
    # (1/15, 14/15). Inhibitory at saturation; excitatory at the
    # flux that produces O*_exc = (1/15)/(_ELISE_G0_EXC * 14)/(_ELISE_G0_INH)
    # NOTE: solving the matching ratio for the REST state. See spec
    # §"Step 4". Concretely: we want
    #     (g0_exc · O*_exc_rest) / (g0_inh · O*_inh_rest) = 1/14
    # with O*_inh_rest ≈ _O_SAT_INH (inhibitory at saturation):
    _O_INH_REST = _O_SAT_INH
    _O_EXC_REST = (1.0 / 14.0) * (_ELISE_G0_INH / _ELISE_G0_EXC) * _O_INH_REST
    _FUER_ELISE_PHI_EXC_REST = _calibrate_phi_for_target_open_fraction(
        _O_EXC_REST, **_ELISE_KIN_EXC,

3.  Add the migration method next to `_migrate_legacy_elise_stim`
    (project.py:820):

        def _migrate_legacy_elise_kinetics_units(self) -> None:
            """Convert pre-kinetic opsin stims (values in [0,1]) to photon flux.

            Detection: external_simulate_path is ELISE, opsin stims
            exist, loaded schema_version < 2, and stim values are in
            [0, 2] (allows tiny float noise above 1.0). When detected,
            apply the inverse Hill using the default kinetic
            parameters to convert each value to photon flux.

            The migration uses the DEFAULTS from
            `Elise.DEFAULT_PARAMS`, not whatever happens to be in
            `external_simulate_params`. If a user has hand-tuned k_a_max
            and saved, the archive will carry schema_version >= 2 and
            this migration won't fire.
            """
            if self.external_simulate_path != "neuroseq:elise":
                return
            if getattr(self, "_loaded_schema_version", 1) >= 2:
                return
            if "opsin_exc" not in self.stim_arrays or "opsin_inh" not in self.stim_arrays:
                return

            exc = self.stim_arrays["opsin_exc"]
            inh = self.stim_arrays["opsin_inh"]
            exc_max = float(np.max(np.abs(exc.values))) if exc.values.size else 0.0
            inh_max = float(np.max(np.abs(inh.values))) if inh.values.size else 0.0
            if exc_max > 2.0 or inh_max > 2.0:
                # Values are already in flux units; nothing to migrate.
                return

            from neuroseq.example_models.elise import DEFAULT_PARAMS
            def _flux_for(O_target: float, side: str) -> float:
                k_a_max = float(DEFAULT_PARAMS[f"k_a_max_{side}"]["default"])
                phi_m   = float(DEFAULT_PARAMS[f"phi_m_{side}"]["default"])
                k_d     = float(DEFAULT_PARAMS[f"k_d_{side}"]["default"])
                k_r     = float(DEFAULT_PARAMS[f"k_r_{side}"]["default"])
                from neuroseq.example_projects import (
                    _calibrate_phi_for_target_open_fraction,
                )
                # Old fractional g maps to target open fraction via g0:
                # g_old = (g0_side · O*_target), so O*_target = g_old / g0_side.
                g0 = float(DEFAULT_PARAMS[f"g0_{side}"]["default"])
                O_target_clamped = min(max(O_target / g0, 0.0), 0.999)
                return _calibrate_phi_for_target_open_fraction(
                    O_target_clamped, k_a_max, phi_m, k_d, k_r,
                )

            # Vectorise via np.vectorize — the migration runs once at load.
            v_exc = np.vectorize(lambda x: _flux_for(float(x), "exc"))(exc.values)
            v_inh = np.vectorize(lambda x: _flux_for(float(x), "inh"))(inh.values)

            exc.values = v_exc.astype(np.float32)
            inh.values = v_inh.astype(np.float32)
            exc.units = "mm^-2 s^-1"
            inh.units = "mm^-2 s^-1"
            self.logger.info(
                "Migrated pre-kinetic ELISE opsin stims (values in [0,1]) "
                "to photon-flux density (mm^-2 s^-1)."
            )

is an approximation: simulating the migrated archive yields `u_tgt`
values within ~1% of the legacy `u_tgt` for the Für-Elise defaults.
This is the trade-off the spec accepts (`test_legacy_pre_kinetic_archive_migrates_to_photon_flux`
asserts ≤ 1% deviation). If the user's archive uses non-default opsin
values, deviations can be larger — that's why the migration logs
a warning-level info message.

NOTES
────────────────────────────────────────────────────────────────────────────────────────────

- The spec's `pyrho_6state_chr2_project` (example_projects.py:1342)
  is a separate, untouched example project for characterising opsins
  in voltage clamp. **Do not modify it.** It coexists with the
  ELISE kinetic layer.

- The unit string `"mm^-2 s^-1"` is plain ASCII; don't use
  `"mm⁻² s⁻¹"` (superscripts) because some downstream serialisation
  paths assume ASCII.

- Forward Euler is sufficient at the actual `dt_ms = 0.1` default
  (k_a_max·dt = 0.1, very stable). If the spec's `if k_a_max*dt > 0.5`
  guard is ever needed, it's a one-line addition — but per SPEC
  DEVIATION 2, do NOT add it in this implementation.

- Kinetic state arrays are NOT serialised. Reload starts from
  `O = D = 0` everywhere — the kinetic transient re-builds within a
  few ms. The Für-Elise default is 8 × 240 ms cycles; the first 10
  ms of the first event has a slightly-different `u_tgt` trajectory
  on a freshly-loaded archive than on a session that ran continuously
  for hours. This is the right trade-off (per spec §"Non-goals").

- The migration test `test_legacy_pre_kinetic_archive_migrates_to_photon_flux`
  needs a helper to write an archive without `schema_version`. Easiest
  path: save normally, then re-open the zip, mutate
  `project_metadata.json`, write back. Both the original and the
  migrated archives go through `Project.load`.

- The new opsin parameters land in the "Opsin (excitatory)" and
  "Opsin (inhibitory)" groups. The model editor's parameter tree
  renders groups as collapsible blocks by string match on the `group`
  field — no other UI changes needed. Confirmed by inspection of
  `model_editor.py`.
