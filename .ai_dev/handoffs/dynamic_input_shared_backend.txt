BACKGROUND — read before touching anything

All three dialogs implement the same "closed-loop routine" shape: append a
stim block, ask the host app to run Brian2 forward over it, react to the
result in `simulation_finished()` by either finishing or deciding and
appending the next block. This was a DELIBERATE prior choice, not an
oversight — when RheobaseDialog was built (see
.ai_dev/handoffs/rheobase_dynamic_input_routine.txt), the handoff explicitly
said "A full shared base class is a NON-GOAL for this handoff," to avoid
refactor risk while the second routine was still being proven out. That
tradeoff has now been paid off three times over (StdpWindowDialog repeated
the same duplication again) and it's time to collect on it.

Confirmed duplicated near-verbatim across all three files (same names, same
bodies, only the internal phase-name strings differ):
    - The run/pause/resume/finish flags: `_running`, `_awaiting_simulation`,
      `_paused`, `_pending_simulation_seconds`, `_phase`.
    - `_request_simulation(seconds)` / `_run_to_sample(stop_sample)`.
    - `simulation_finished()` / `simulation_failed(message)` / `_finish(message)`.
    - `_append_block`/`_place_block`: compute a start sample, call
      `self.editor.apply_pattern(...)`, then a "follow" step
      (`chk_follow_input`/`focus_time_range`) that is UNCHANGED by this
      handoff - see CHANGE 4 step 4.
    - The measurement plumbing: `EPSPMeasurement` (defined once, in
      stdp_synaptic_tuning_dialog.py, and imported into stdp_window_dialog.py
      — a dialog importing a dataclass from a sibling dialog module is
      itself a symptom of the missing shared module), plus near-identical
      trace-windowing bodies in `_measure_spikes` (rheobase) and
      `_measure_epsps` (the other two).

Only Qt-chrome helpers are currently shared (`_SelfRaisingDialog`,
`_WheelToScrollFilter`, `_wrap_in_scroll_area`, `_set_native_minimized_position`,
`StimHeatmapWindow` — all still live in stdp_synaptic_tuning_dialog.py and
stay there, untouched by this handoff).

--------------------------------------------------------------------------------
Bug being fixed alongside the extraction: silent gap inflation
--------------------------------------------------------------------------------

`_append_block` today computes `start = max(stim.values.shape[0], current_sample)`
where `current_sample = ceil(project.b2_model.get_sim_time_secs() / stim.dt)`.
This is meant to always agree with the array's own length, but
`Project.run_simulation` (project.py:1350-1368) does this BEFORE running:

    self.pad_stim_arrays(
        self.b2_model.get_sim_time_secs() + time_seconds + stim_array_padding_seconds
    )

`stim_array_padding_seconds` comes from a global, user-configurable setting
(`Settings.stim_padding_secs`, default 0, changed via File > "Input Automatic
Padding", gui.py:2761). `pad_stim_arrays` only ever GROWS an array
(`ResizableReversibleAction._ensure_padded`, stim_array_modifier.py:108-110,
confirms there is no complementary shrink anywhere in that call path). So
whenever that setting is nonzero, every simulation run silently zero-pads the
stim array beyond the block's intended end — while the simulation clock only
advances by `time_seconds`. `_append_block`'s `max(...)` then prefers the
(now inflated) array length over the true simulation clock, and the NEXT
probe's gap silently grows by the padding amount, on top of whatever the
routine's own recovery/response parameters configured — invisibly, with
nothing in the log or plots showing why.

The fix: trim the array back to the true simulation head, via the EXISTING
`StimEditor.reset_stim_array()` (stim_editor.py:405-425), before every
append — not just once at routine start, which is all that happens today.
Its own docstring already guarantees safety: "never cuts into the recorded
simulation (it only removes the unused trailing tail)," and it short-circuits
cheaply (stim_editor.py:423-424) when there's nothing to trim, so calling it
unconditionally before every block costs nothing extra in the common
(padding=0) case and silently self-corrects in the case it doesn't.

Move `EPSPMeasurement` out of stdp_synaptic_tuning_dialog.py (currently at

    from __future__ import annotations

    from dataclasses import dataclass

    import brian2.numpy_ as np

    from neuroseq.data import TraceData
    from neuroseq.resources.analysis_plugins.epsp_amplitudes import _to_mv
    from neuroseq.resources.analysis_plugins.epsp_amplitudes import detect_epsps
    from neuroseq.rheobase import count_spikes


    @dataclass(frozen=True)
    class EPSPMeasurement:
        amplitude: float
        pulse_amplitudes: tuple[float, ...]
        units: str = "mV"


    class NoEpspDetected(ValueError):
        """No EPSP was found in a probe's response window.

        A ValueError subclass so existing `except ValueError:` call sites in
        the dialogs keep working unchanged - StdpSynapticTuningDialog today
        catches plain ValueError around its measurement call, and
        StdpWindowDialog catches a routine-local `_NoEpspDetected`; both
        collapse onto this one type with no observable change.
        """


    def _trace_row_mv(trace: TraceData, neuron_id: int) -> tuple[np.ndarray, float]:
        matches = np.flatnonzero(trace.indices == neuron_id)
        if matches.size == 0:
            raise ValueError(f"Neuron {neuron_id} is not recorded in the trace.")
        trace_mv = _to_mv(trace.traces[int(matches[0])], trace.units)
        dt_ms = 1000.0 * trace.dt
        return trace_mv, dt_ms


    def measure_spike_count(
        trace: TraceData,
        neuron_id: int,
        onset_seconds: float,
        window_ms: float,
        threshold_mv: float,
    ) -> int:
        """Count spikes in [onset, onset + window_ms] for `neuron_id`.

        Mirrors RheobaseDialog._measure_spikes's windowing exactly - the
        caller computes `window_ms` (today:
        `self._current_duration_ms + self.spn_response_ms.value()`).
        """
        trace_mv, dt_ms = _trace_row_mv(trace, neuron_id)
        onset_ms = 1000.0 * onset_seconds
        start = max(0, int(np.floor(onset_ms / dt_ms)))
        stop = min(trace_mv.size, int(np.ceil((onset_ms + window_ms) / dt_ms)) + 1)
        return count_spikes(trace_mv[start:stop], threshold_mv)


    def measure_epsp(
        trace: TraceData,
        neuron_id: int,
        probe_pulse_times_s: list[float],
        baseline_ms: float,
        response_ms: float,
    ) -> EPSPMeasurement:
        """Associate detect_epsps' detections with each probe pulse time and
        average them. Mirrors the two existing `_measure_epsps` bodies
        exactly, including the "largest candidate in window wins" tie-break
        (a spurious smaller deflection must not be picked over the real
        EPSP)."""
        trace_mv, dt_ms = _trace_row_mv(trace, neuron_id)
        amplitudes: list[float] = []
        for pulse_time in probe_pulse_times_s:
            onset_ms = 1000.0 * pulse_time
            start_ms = max(0.0, onset_ms - baseline_ms)
            stop_ms = onset_ms + response_ms
            start = max(0, int(np.floor(start_ms / dt_ms)))
            stop = min(trace_mv.size, int(np.ceil(stop_ms / dt_ms)) + 1)
            if start >= trace_mv.size:
                trace_duration_ms = trace_mv.size * dt_ms
                raise NoEpspDetected(
                    f"The selected trace ends at {trace_duration_ms:.3f} ms, "
                    f"before the probe at {onset_ms:.3f} ms. Select the "
                    "current simulation voltage trace and try again."
                )
            detection = detect_epsps(trace_mv[start:stop], dt_ms)
            relative_onset_ms = onset_ms - start * dt_ms
            sample_tolerance_ms = 0.5 * dt_ms
            candidates = detection.amplitudes_mv[
                (detection.times_ms >= relative_onset_ms - sample_tolerance_ms)
                & (
                    detection.times_ms
                    <= relative_onset_ms + response_ms + sample_tolerance_ms
                )
            ]
            if candidates.size == 0:
                raise NoEpspDetected(
                    f"No EPSP was detected after the probe at {onset_ms:.3f} ms."
                )
            amplitudes.append(float(np.max(candidates)))
        return EPSPMeasurement(
            amplitude=float(np.mean(amplitudes)),
            pulse_amplitudes=tuple(amplitudes),
        )

Double check `detect_epsps`'s return type (`amplitudes_mv`/`times_ms` field
names) against the actual current signature in
`neuroseq/resources/analysis_plugins/epsp_amplitudes.py` before pasting this
in — copy the exact field names from there, don't assume the ones above are

CHANGE 2 — src/neuroseq/dynamic_input_blocks.py (new, no Qt) — THE GAP FIX LIVES HERE
════════════════════════════════════════════════════════════════════════════════════════════

    from __future__ import annotations

    from typing import Protocol

    import brian2.numpy_ as np

    from neuroseq.project import Project
    from neuroseq.stim import StimArray


    class BlockEditor(Protocol):
        """What appending a block needs from StimEditor."""

        def apply_pattern(self, neuron_slice, time_slice, new_values: np.ndarray) -> None: ...
        def reset_stim_array(self) -> None: ...


    def append_block(editor: BlockEditor, stim: StimArray, block: np.ndarray) -> int:
        """Trim `stim` back to the current simulation head, then write
        `block` immediately after it. Returns the sample index the block was
        written at.

        The trim (`editor.reset_stim_array()`) is what guarantees a
        routine's configured inter-block gap is the ONLY thing separating
        two blocks: without it, the project-wide "Input Automatic Padding"
        setting can silently pad the array beyond a block's own end during a
        simulation run, and the next block would be appended after that
        extra padding too. reset_stim_array() only ever removes UNSIMULATED
        trailing padding - never anything already delivered to the
        simulation - and is a cheap no-op when there's nothing to trim, so
        it's safe and cheap to call before every block, not just the first.
        Because of this, the start sample is simply `stim.values.shape[0]`
        after the trim - there is no longer a need to reconcile it against
        the separately-computed simulation-clock sample the way the old
        per-dialog `max(stim.values.shape[0], current_sample)` did.

        Does NOT touch the live view/camera - that stays entirely the
        calling dialog's own responsibility (its existing
        `chk_follow_input`/`focus_time_range` logic is unchanged by this
        handoff; call it, if at all, AFTER this function returns, exactly
        where the dialog calls it today relative to the old
        `_append_block`/`_place_block` body).
        """
        editor.reset_stim_array()
        start = stim.values.shape[0]
        editor.apply_pattern(
            slice(0, stim.values.shape[1]),
            slice(start, start + block.shape[0]),
            block,
        )
        return start


    def run_to_sample(project: Project, stim: StimArray, stop_sample: int) -> float:
        """Seconds to simulate forward to reach `stop_sample` on `stim`'s dt."""
        current_time = project.b2_model.get_sim_time_secs()
        return max(stim.dt, stop_sample * stim.dt - current_time)

CHANGE 3 — src/neuroseq/dynamic_input_routine.py (new, no Qt)
════════════════════════════════════════════════════════════════════════════════════════════

    from __future__ import annotations

    from collections.abc import Callable
    from typing import Protocol


    class SimulationHost(Protocol):
        """What a routine backend needs to trigger a Brian2 run."""

        def request_simulation(self, seconds: float) -> None: ...


    class DynamicInputDialog(Protocol):
        """The contract StimEditor._dynamic_input_dialogs() (stim_editor.py,
        see CHANGE 6) already assumes of every cached routine dialog."""

        def simulation_finished(self) -> None: ...
        def simulation_failed(self, message: str) -> None: ...
        def refresh(self) -> None: ...
        def apply_theme(self, theme: str) -> None: ...


    class RoutineBackend:
        """Run/pause/resume/finish plumbing shared by every closed-loop
        routine.

        A subclass owns its own phase graph: its `_phase`/domain-specific
        state, and `_advance()`, which reacts to a just-finished simulation
        for whatever phase it's currently in and either calls
        `self.finish(...)` or does this iteration's bookkeeping and calls
        `self.request_simulation(...)` for the next one. This class owns
        exactly what was previously copy-pasted identically across all
        three dialogs: the running/awaiting/paused flags, the
        pause-then-defer-next-request behavior, and _finish's reset
        sequence. No Qt import anywhere in this class - it is unit-testable
        with a fake SimulationHost and no QApplication.
        """

        def __init__(self, host: SimulationHost) -> None:
            self._host = host
            self.running = False
            self.awaiting_simulation = False
            self.paused = False
            self.pending_simulation_seconds: float | None = None
            self.phase = "idle"
            self.on_log: Callable[[str], None] | None = None
            self.on_finished: Callable[[str], None] | None = None

        def begin(self) -> None:
            self.running = True
            self.paused = False
            self.pending_simulation_seconds = None

        def toggle_pause(self) -> None:
            self.paused = not self.paused
            self._log(
                "Paused - the routine will hold after its current step."
                if self.paused
                else "Resumed."
            )
            if not self.paused and self.pending_simulation_seconds is not None:
                seconds = self.pending_simulation_seconds
                self.pending_simulation_seconds = None
                self.awaiting_simulation = True
                self._host.request_simulation(seconds)

        def request_simulation(self, seconds: float) -> None:
            if self.paused:
                self.pending_simulation_seconds = seconds
                self._log(
                    "Paused - next iteration queued; click Resume to continue."
                )
                return
            self.awaiting_simulation = True
            self._host.request_simulation(seconds)

        def simulation_finished(self) -> None:
            if not self.running or not self.awaiting_simulation:
                return
            self.awaiting_simulation = False
            self._advance()

        def simulation_failed(self, message: str) -> None:
            if self.running and self.awaiting_simulation:
                self.finish(f"Simulation failed: {message}")

        def finish(self, message: str) -> None:
            self.running = False
            self.awaiting_simulation = False
            self.paused = False
            self.pending_simulation_seconds = None
            self.phase = "idle"
            self._log(message)
            if self.on_finished is not None:
                self.on_finished(message)

        def _log(self, message: str) -> None:
            if self.on_log is not None:
                self.on_log(message)

        def _advance(self) -> None:
            raise NotImplementedError

   `_request_simulation` used to do at the Qt-signal level:

        def request_simulation(self, seconds: float) -> None:
            self.simulation_requested.emit(seconds)

   (The pause-aware deferral logic that used to live in
   `_request_simulation` is now entirely inside `RoutineBackend` - this new
   `request_simulation` is the raw, unconditional "emit the signal" leaf
   the backend calls once it has already decided not to defer.)
