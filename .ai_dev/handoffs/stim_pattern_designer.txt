stim_pattern_designer — "Design stimulation pattern" guided generator dialog [IMPLEMENTED]
==========================================================================================

A new non-modal dialog (launched from a toolbar button in `stim_editor`) that
guides the user through building common stimulus patterns: sequential and
simultaneous trains across all neurons, the Für Elise musical phrase across
the first 13 neurons, and per-neuron pulse trains with the Constant /
Linear / Logarithmic / Random intensity profiles that already exist
elsewhere. Each Apply places one pattern on the currently selected stim
array, automatically advances a "start time" cursor so successive Applies
stack cleanly, and is fully undoable — even when padding the project to fit.

Files to change:
    src/neuroseq/stim_editor.py             (toolbar action + apply_pattern method + invoke dialog)
    src/neuroseq/stim_array_modifier.py     (new ResizableReversibleAction class)

Files to create:
    src/neuroseq/stim_patterns.py           (pure-math pattern generators, no Qt)
    src/neuroseq/stim_pattern_dialog.py     (non-modal Qt dialog)
    tests/test_stim_patterns.py             (pure-math tests)
    tests/test_stim_pattern_dialog.py       (Qt + undo integration tests)


────────────────────────────────────────────────────────────────────────────────────────────
DEFAULTS — match the Getting Started example
────────────────────────────────────────────────────────────────────────────────────────────

The "Getting Started" project (example_projects.py:165-187) is the
reference: 100 ms pulses, 18 ms inter-pulse gap, amplitude 1.0,
units "siemens", stim_dt 1 ms. All four pattern types take the same
inputs (where they apply):

    pulse_duration_ms : float = 100.0
    magnitude         : float = 1.0
    units             : str   = (preserved from current stim array — read-only display)
    inter_pulse_ms    : float = 18.0   # gap between pulses / events
    repeats           : int   = 1      # only Simultaneous, Für Elise, and per-neuron use this

`units` is shown as a label, not editable: stim array units are owned by the
stim array itself and changing them is an `Edit stim array` operation. The
label exists so the user knows what scale `magnitude` is in.

For the per-neuron intensity-profile patterns (Constant / Linear / Log /
Random), the magnitude field expands to TWO fields when the profile is not
Constant — start/end for Linear, start/end for Log, min/max for Random —
matching the existing `StimIntensityDialog` exactly.

PATTERN MATH — src/neuroseq/stim_patterns.py (new, pure functions)
────────────────────────────────────────────────────────────────────────────────────────────

All generators return `np.ndarray` of shape `(n_samples, n_neurons)` and
take a `dt_seconds` argument used to convert ms → samples via
`round(ms / 1000 / dt_seconds)`.

1.  `generate_sequential(n_neurons, pulse_ms, ipi_ms, magnitude, dt_seconds) -> ndarray`

    Per the Getting Started example. Each neuron is stimulated alone, in
    order 0..n-1, for `pulse_ms`, with `ipi_ms` gap between pulses.
    Returns shape `(n_neurons * (pulse_n + ipi_n), n_neurons)`.

2.  `generate_simultaneous(n_neurons, pulse_ms, ipi_ms, magnitude, repeats, dt_seconds) -> ndarray`

    All neurons fire at once. One "event" is `pulse_n` on samples followed
    by `ipi_n` zero samples. Stacked `repeats` times.
    Returns shape `(repeats * (pulse_n + ipi_n), n_neurons)`.

3.  `generate_fuer_elise(n_neurons, pulse_ms, ipi_ms, magnitude, repeats, dt_seconds) -> ndarray`

    Uses the existing `_FUER_ELISE_INTRO` event list (24 events with 13
    pitches). Reuse the constant from `example_projects.py` by lifting it
    into `stim_patterns.py` (and importing the existing one from
    `example_projects` for back-compat). Each event lasts `pulse_n`
    samples followed by `ipi_n` zeros. Multi-pitch chord events write
    `magnitude` simultaneously to each chord pitch. The phrase is
    repeated `repeats` times back-to-back.

    Neuron handling:
        - Use only the first `min(n_neurons, 13)` pitches.
        - For chord events whose other pitch indices exceed `n_neurons-1`,
          those pitches are silently dropped (clip). If a chord's only
          notes are all out of range the event becomes silent. This
          matches "use any number of available neurons, clipping the
          pattern accordingly".

    Returns shape `(repeats * 24 * (pulse_n + ipi_n), n_neurons)`.
    Note the trailing IPI after the last event is INCLUDED — required so
    repeats stack cleanly.

4.  `generate_per_neuron(neuron_index, n_neurons, pulse_ms, ipi_ms,
        profile, value1, value2, repeats, dt_seconds) -> ndarray`

    A single-neuron train of `repeats` pulses on the column
    `neuron_index`, with intensity per pulse determined by `profile`:

        profile = DrawStimType.Constant     → every pulse has value1
        profile = DrawStimType.Linear       → np.linspace(value1, value2, repeats)
        profile = DrawStimType.Logarithmic  → np.logspace(log(value1), log(value2), repeats)
                                              (require value1>0, value2>0)
        profile = DrawStimType.Random       → np.random.uniform(value1, value2, repeats)
                                              (treat value1 as min, value2 as max — same as StimIntensityDialog)

    All other neuron columns are zero.

    Returns shape `(repeats * (pulse_n + ipi_n), n_neurons)`.

5.  `pattern_total_samples(...)` — small helpers to compute the resulting
    length without building the full array (used to validate against the
    current stim array's length without allocating).

All five generators include a **trailing IPI of `ipi_n` zero samples** at
the very end. This is required so the user's next Apply can land
immediately after without the two pulses fusing.

Edge cases:
    - pulse_ms <= 0  → ValueError
    - ipi_ms < 0     → ValueError (zero is allowed for back-to-back pulses)
    - magnitude == 0 → allowed (writes zeros; effectively just advances the
                       cursor — useful for inserting deliberate gaps)
    - repeats < 1    → ValueError
    - Logarithmic with non-positive value1/value2 → ValueError

PROJECT-LEVEL UNDO — src/neuroseq/stim_array_modifier.py
────────────────────────────────────────────────────────────────────────────────────────────

Applying a pattern may require padding the target stim array to fit. The
project's `pad_stim_arrays` pads EVERY stim array to the new length, which
breaks the existing slice-based undo model (other stim arrays' modifiers
hold slices that may no longer be in-bounds after a future undo shrinks
the arrays).

ADD a new compound action class `ResizableReversibleAction` next to
`ReversibleAction`:

    class ResizableReversibleAction:
        """One-step undo for: pad project to new length + overwrite slice
        on a single target stim array. Restores all arrays' previous
        lengths and the target's previous values on undo."""

        def __init__(
            self,
            project: Project,
            target_stim_name: str,
            neuron_slice: slice,
            time_slice: slice,
            new_values: np.ndarray,
            stim_widget: StimWidget,
        ) -> None:
            self.project = project
            self.target_stim_name = target_stim_name
            self.neuron_slice = neuron_slice
            self.time_slice = time_slice
            self.new_values = np.array(new_values, copy=True)
            self.stim_widget = stim_widget
            # Snapshot full pre-state of every stim array in the project.
            self.before_lengths: dict[str, int] = {
                name: arr.values.shape[0]
                for name, arr in project.stim_arrays.items()
            }
            self.before_target_values: np.ndarray | None = None  # set in __call__
            # The new total length needed (in samples on the target's dt).
            self.new_length = time_slice.stop

        def __call__(self, stim_array: StimArray, stim_widget: StimWidget) -> None:
            # Pad every array whose length is < new_length (computed in
            # target dt — see "PAD ALIGNMENT" below). Snapshot the
            # target's old slice values BEFORE overwriting.
            self._ensure_padded()
            target = self.project.stim_arrays[self.target_stim_name]
            self.before_target_values = target.values[
                self.time_slice, self.neuron_slice
            ].copy()
            target.values[self.time_slice, self.neuron_slice] = self.new_values
            stim_widget.update_data_slice(
                self.neuron_slice, self.time_slice, self.new_values
            )
            self.project.update_limits()

        def undo(self, stim_array: StimArray, stim_widget: StimWidget) -> None:
            # Restore target slice values, then truncate every array back
            # to its pre-action length.
            if self.before_target_values is not None:
                target = self.project.stim_arrays[self.target_stim_name]
                target.values[self.time_slice, self.neuron_slice] = (
                    self.before_target_values
                )
            for name, old_length in self.before_lengths.items():
                if name not in self.project.stim_arrays:
                    continue
                arr = self.project.stim_arrays[name]
                if arr.values.shape[0] > old_length:
                    arr.values = arr.values[:old_length, :]
            self.project.update_limits()

        def _ensure_padded(self) -> None:
            # Convert self.new_length (samples in target dt) to seconds,
            # then call project.pad_stim_arrays which handles per-array
            # dt conversion.
            target_dt = self.project.stim_arrays[self.target_stim_name].dt
            new_secs = self.new_length * target_dt
            self.project.pad_stim_arrays(new_secs)

The existing `StimArrayModifier.do/undo/redo` call `action(stim_array,
stim_widget)` and `action.undo(stim_array, stim_widget)`. Both methods on
the new class have matching signatures (they ignore `stim_array` and use
the project reference instead). So no changes are needed to
`StimArrayModifier` itself.

WHAT ABOUT STALE ACTIONS in OTHER modifiers' stacks (or in the same
modifier's stack predating this compound action)?

After a pad, all existing slice ranges in OTHER modifiers' stacks are
still valid (pad only grows). After an undo of the compound action, the
arrays shrink — any older action with `time_slice.stop > new_length`
becomes invalid.

To keep the undo model simple and predictable:

    1. When the editor pushes a `ResizableReversibleAction` onto the
       current modifier, it ALSO clears every OTHER modifier's
       `action_stack` (and resets their `current_index = -1`).

    2. It does NOT clear the current modifier's own prior history.
       Prior slice-based actions whose slices remain in-bounds after a
       future undo of the compound action will still work; ones that
       don't are silently no-op'd via a bounds-check inside
       `ReversibleAction._asign_values` (add a guard there:
       `if self.time_slice.stop > stim_array.values.shape[0] or
       self.neuron_slice.stop > stim_array.values.shape[1]: return`).

    3. Even if pattern Apply does NOT require padding (the array is
       already long enough), still use `ResizableReversibleAction` for
       uniformity. The pad step becomes a no-op (`pad_stim_arrays`
       skips arrays already at-or-beyond `new_secs`), the `before_lengths`
       snapshot equals the current lengths, and undo restores values
       without truncation.

(2) is a small safety net for an edge case; it's documented as a one-line
addition to `ReversibleAction._asign_values`.

DIALOG — src/neuroseq/stim_pattern_dialog.py (new, non-modal)
────────────────────────────────────────────────────────────────────────────────────────────

`StimPatternDialog(QtWidgets.QDialog)` with `setModal(False)`. Two columns
or a single column — single column is simplest. Layout from top:

    [Target] Stim array: <name> (read-only label)         Units: <units> (label)
                                                          dt: <dt_ms> ms

    [Scope]   ( ) All neurons          (•) Specific neuron: [ 0 ▾ ]

    [Pattern type]
        when scope = all neurons:
            (•) Sequential
            ( ) Simultaneous
            ( ) Für Elise
        when scope = specific neuron:
            (•) Constant
            ( ) Linear gradient
            ( ) Logarithmic gradient
            ( ) Random

    [Parameters — fields shown / hidden based on scope + pattern]
        Pulse duration (ms):  [ 100.0 ]
        Inter-pulse interval (ms): [ 18.0 ]
        Magnitude:            [ 1.0 ]                  (Constant / Sequential / Simultaneous / Für Elise)
        Initial magnitude:    [ 1.0 ]                  (Linear / Log)
        Final magnitude:      [ 2.0 ]                  (Linear / Log)
        Minimum magnitude:    [ 0.0 ]                  (Random)
        Maximum magnitude:    [ 1.0 ]                  (Random)
        Repeats:              [ 1 ]                    (Simultaneous, Für Elise, per-neuron)
        Start time (ms):      [ 0.0 ]                  (auto-advances on Apply)

    [Buttons]
        [Apply]   [Reset start time]   [Clear stim array]   [Close]

Behaviour:

- `set_context(ctx)` populates: target stim name, n_neurons (caps the
  neuron-index spin's max), units label, dt_ms label. Also resets the
  pattern type radios to a sensible default given the current scope.

- Scope toggle: All vs. Specific. Switching from All to Specific shows
  the neuron-index spinbox and the per-neuron pattern radios; the all-
  neurons radios are hidden. The reverse on switching back.

- Pattern radio toggle: shows/hides the magnitude fields and the
  Repeats spin per the table above.

- `Apply` button:
    1. Validate all numeric inputs (positive pulse_ms, non-negative
       ipi_ms, repeats >= 1, magnitudes finite, plus Log requires
       positive). Show a `QMessageBox.warning` on failure and abort.
    2. Build the pattern via the matching `generate_*` function.
    3. Compute `start_samples = round(start_time_ms / 1000 / dt)` and
       `end_samples = start_samples + pattern.shape[0]`.
    4. Construct `time_slice = slice(start_samples, end_samples)` and
       `neuron_slice = slice(0, n_neurons)`.  (Always full-width on the
       neuron axis — the pattern matrix itself has zeros where it doesn't
       paint. This keeps the undo slice math consistent.)
    5. Call `self.editor.apply_pattern(neuron_slice, time_slice, pattern)`.
    6. Auto-advance: `start_time_ms = (end_samples + ipi_n) * dt * 1000`.
       Note `pattern` already includes a trailing IPI; the auto-advance
       does NOT add a second IPI — the cursor lands exactly where the
       trailing IPI ends so the next Apply starts a clean pulse. (The
       trailing IPI is *inside* the pattern's `time_slice`.)

       Wait — re-read the requirement: "the next pattern can start
       safely" and "add an inter-pulse interval automatically at the end
       of every stimulation pattern". The trailing IPI is the safe gap.
       Auto-advance to `end_samples` (which IS the position right after
       the trailing IPI, because the trailing IPI is the last `ipi_n`
       samples of `pattern`). So:

           new_start_ms = end_samples * dt * 1000

- `Reset start time` button: sets the Start time spin back to 0.

- `Clear stim array` button: calls `self.editor.clear_stim_array()` —
  reuses the existing undoable clear path.

- `Close` button: `self.hide()`. Don't destroy the dialog; the editor
  reuses the same instance.

- The dialog reflects context changes: when the user picks a different
  stim array in the editor, `set_context` updates the target/units/dt
  labels and clamps the neuron-index spin to the new n_neurons. The
  Start time cursor is NOT reset on context change (user can hit Reset
  if they want).

PAD ALIGNMENT (read this before implementing the pad path)
────────────────────────────────────────────────────────────────────────────────────────────

`project.pad_stim_arrays(total_time_seconds)` pads each array
independently using its own `dt`. So if other stim arrays in the project
have different `dt` than the target, their sample counts after pad will
differ. That's already the case in the codebase and is fine.

The compound action stores per-array sample counts BEFORE pad
(`before_lengths`), so on undo it can restore each array's exact
pre-pad shape regardless of dt mismatches. Use `arr.values.shape[0]`
(samples), not seconds, in `before_lengths` for exact restoration.

────────────────────────────────────────────────────────────────────────────────────────────
NON-GOALS
────────────────────────────────────────────────────────────────────────────────────────────

- ADDING values to existing stim contents. Each Apply overwrites the
  target region (slice). The user wanted overwrite.

- WRITING into more than one stim array per Apply. Für Elise stays a
  single-array generator — no opsin exc/inh pair generation, no second
  stim array.

- A "preview before Apply" toggle. The user can Apply → eyeball → undo.

- KEYBOARD SHORTCUT. The button has no shortcut. The dialog is mouse-
  driven; users who want it can configure a shortcut on the toolbar
  action later.

- AUTO-SHRINKING THE PROJECT after an Apply that doesn't fill the
  previously padded length. The trailing IPI inside `pattern` plus the
  cursor advance leaves whatever pad existed alone.

- AUTOMATIC RE-RUN of a previous Apply when parameters change. The user
  must hit Apply each time.

- A "PROGRESS" indicator for very long patterns. Pattern generation is
  pure numpy and bounded — even Für Elise × 100 is sub-millisecond.
