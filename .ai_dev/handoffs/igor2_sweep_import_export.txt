==================================================================
Branch: <pick one off main>
Repo:   /mnt/live3/svintila/neuroseq
Date:   2026-05-19


PROBLEM
-------
Two missing features on the Igor2 import/export side, both centred on
the same concept: an Igor wave can be 2-D `(samples, sweeps)`, where
each column is one trial of the same protocol.

1. IMPORT side. `parse_igor_binary_wave_data` (src/neuroseq/importer_igor2.py)
   rejects any wave whose data isn't 1-D after `np.squeeze`. A real
   SutterPatch IVstep recording has shape `(30000, 7)` — 30 000 samples
   × 7 sweeps — which the squeeze can't reduce and the importer raises
   "Only 1-dimensional Igor Binary Waves can be imported into NeuroSeq".
   Test file proven to trigger this:
   `/mnt/live3/svintila/random/igor2_files/test_files/R5_S1_IVstep.ibw`
   (wData shape (30000, 7), sfA[0]=5e-5, dataUnits='A', dimUnits[0]='s').

   The desired behaviour is to **concatenate sweeps end-to-end into a
   single 1-D wave** (sweep 0 then sweep 1 … then sweep N−1) and import
   that. This keeps the rest of the importer (resampler, single-column
   StimArray builder, single-row TraceData builder) unchanged. The cost
   is that inter-sweep gaps from the original recording (Igor's
   `SweepStartTimes` note) are not reconstructed — the sweeps abut. For
   the patch-clamp use case where sweeps are well-spaced enough that the
   cell returns to rest, this loses nothing observable. The dialog must
   show an info label so this isn't a silent surprise.

2. EXPORT side. The single-wave IBW exporter (`Igor2SingleWaveExportDialog`
   + `export_igor2_ibw`) writes only 1-D waves today. Neuroseq has a
   loop-detection helper (`_detect_period` in stim_loop_dialog.py) that
   finds the smallest exact-repeating block in a stim. We want a
   checkbox in the export dialog — "Export as sweeps (auto-detect period)"
   — that, when enabled, runs the detector on the column being exported.
   If a period is found and the column splits evenly into ≥2 sweeps,
   the exporter writes a 2-D IBW (shape `(period, n_sweeps)`) with Igor
   column-major byte order. Igor Pro then opens the file as a multi-sweep
   wave the user can plot stacked, overlaid, or averaged. If no period
   is detected (or the result would be a single sweep), the exporter
   falls back to 1-D and the dialog surfaces a small inline status
   note. CSV path is unchanged — sweeps are an IBW-only concept here.


TASK OVERVIEW
-------------
A. Promote `_detect_period` from `stim_loop_dialog.py` to `utils.py` as a
   public `detect_period` so both the loop dialog and the new export
   checkbox call the same function. The existing loop dialog switches
   to importing it from there.

B. Multi-sweep IBW import:
   - `parse_igor_binary_wave_data` accepts shape `(N,)` and `(N, S)`,
     rejects 3-D+.
   - When the input is 2-D, concatenate column-major into 1-D
     (`wData.ravel(order='F').astype(float32)`).
   - `IgorWave` records `n_sweeps` and `samples_per_sweep` (default 1 / N
     for 1-D inputs). Used only by the dialog info label and reports.
   - `IgorImportReport` and `IgorTraceImportReport` gain `n_sweeps` and
     `samples_per_sweep` fields for the post-import message.
   - `igor_import_dialog.py` and `igor_trace_import_dialog.py` show an
     info label when `wave.n_sweeps > 1`. No new controls.

C. Multi-sweep IBW export:
   - `_write_ibw_v5` accepts either a 1-D `ndarray` (current behaviour)
     or a 2-D `(samples, sweeps)` ndarray. For 2-D it writes
     `nDim = [samples, sweeps, 0, 0]`, `npnts = samples * sweeps`, and
     serialises the data block in **column-major** order (Igor's wire
     format for multi-D waves).
   - `export_igor2_ibw` gains a new keyword `as_sweeps: bool = False`.
     When `True`, the exporter calls `detect_period` on the selected
     column AFTER scaling; if a usable period is found, reshape to
     `(period, n_sweeps)` and write 2-D. If not, write 1-D and report
     that fallback to the caller via a new `Igor2SingleWaveExport.n_sweeps`
     field (set to 1 in the fallback case, `>1` on success).
   - `Igor2SingleWaveExportDialog` adds a checkbox "Export as sweeps
     (auto-detect period)" plus an inline status label. The checkbox is
     enabled only when the chosen format is `.ibw` (greyed out the
     moment the user picks `.csv` from the file-save dialog — but
     because file format is picked AFTER the dialog closes, see
     "design note" below for the actual UX).
   - `gui.py`'s `btn_export_igor2_single_wave_clicked` forwards the
     checkbox through to `export_igor2_ibw` (CSV path silently ignores
     it).


DESIGN NOTE — checkbox timing
-----------------------------
The current export flow is: dialog (pick name/neuron/unit/scaling) →
file-save dialog (pick .ibw or .csv). The "Export as sweeps" checkbox
must therefore live in the **first** dialog. The simplest UX:

- Checkbox is always enabled in the first dialog.
- Below it, a non-editable status label shows the detection result for
  the **currently selected neuron**, updating when the neuron combo
  changes:
    - "Period detected: 300 samples × 6 sweeps (1800 total)" — sweep
      export will work.
    - "No periodic block detected — will fall back to single-sweep
      export." — informs the user but does not block.
- When the user picks `.csv` at the file-save dialog, the checkbox is
  silently ignored (CSV is 1-D by nature). A one-line warning is
  emitted via `logger.info` so the silence isn't total.

Detection runs in the dialog (so the user sees the status) AND in the
exporter (so it does the actual reshape with the post-scaling values).
The status preview is computed on the raw `stim_array[:, idx]`; the
authoritative reshape uses `scaled_values`. The two agree because
`detect_period` is scale-invariant for non-zero scaling factors (the
exact-equality check on `values[:n-period]` vs `values[period:]`
survives uniform scaling). The dialog status is a UX hint; the
exporter does the real work.


SCOPE (explicit cuts)
---------------------
- Do NOT add `.pxp` sweep export. PXP already has natural per-array
  waves; the loop-detect-and-split semantics don't translate cleanly.
- Do NOT add a "use only first sweep" import mode. Default and only
  mode on import: concatenate all sweeps. Selective-sweep import is
  out of scope.
- Do NOT parse the SutterPatch `note` text (ScaleFactor, ScaleOffset,
  SweepStartTimes). The file from the user has ScaleFactor=1 /
  ScaleOffset=0 so this is a no-op for the test file, and a general
  parser of that text blob is a separate concern. Add a TODO comment
  in `parse_igor_binary_wave_data` flagging the note metadata as a
  future improvement.
- Do NOT add inter-sweep gap reconstruction from `SweepStartTimes`.
  Sweeps abut. Document this in the dialog info label.
- Do NOT touch the PXP loader, the trace importer's spike detection,
  or any export path that isn't the single-wave IBW.

        values: np.ndarray,
        *,
        wave_name: str,
        dt: float,
        data_units: str = "",
        x_units: str = "s",
    ) -> bytes:
        data = np.asarray(values, dtype="<f4")

Extend `export_igor2_ibw`:

    def export_igor2_ibw(
        output_path: str | pathlib.Path,
        stim_array: StimArray,
        *,
        wave_name: str,
        neuron_index: int,
        unit_override: str | None = None,
        scaling_factor: float = 1.0,
        as_sweeps: bool = False,
    ) -> Igor2SingleWaveExport:
        # ...existing validation, scaling, sanitisation...
        values = scaled_values  # 1-D, shape (n_samples,)

        n_sweeps_out = 1
        write_values: np.ndarray = values
        if as_sweeps:
            from neuroseq.utils import detect_period
            period = detect_period(values)
            if period is not None and period > 0 and values.size % period == 0:
                sweep_count = values.size // period
                if sweep_count > 1:
                    write_values = values.reshape(sweep_count, period).T
                    write_values = np.ascontiguousarray(write_values)
                    n_sweeps_out = sweep_count
            # else: fall through and emit 1-D

        ibw_bytes = _write_ibw_v5(
            write_values,
            wave_name=sanitized_name,
            dt=float(stim_array.dt),
            data_units=wave_units,
            x_units="s",
        )
        path = pathlib.Path(output_path)
        path.write_bytes(ibw_bytes)
        return Igor2SingleWaveExport(
            experiment_name=sanitized_name,
            neuron_index=neuron_index,
            sample_count=int(stim_array.values.shape[0]),
            n_sweeps=n_sweeps_out,
        )

The `.values.reshape(sweep_count, period).T` produces the
`(period, sweep_count)` layout `_write_ibw_v5` expects. Order: if the
original 1-D wave was `[s0_sweep0, s1_sweep0, ..., s0_sweep1, ...]`
(the natural concatenation our import side now produces) then
`reshape(sweep_count, period)` groups by sweep first (each row = one
sweep), and `.T` puts samples on axis 0 / sweeps on axis 1 — which
matches Igor's column-major layout when serialised.

If the 1-D wave was authored in some other order (e.g. interleaved),
`detect_period` will not find a period of `period_length` and the
2-D path will not engage. So no silent misreshape.
