stdp_window_routine — "STDP timing window (LTP/LTD vs Δt)" Design dynamic input routine  [IMPLEMENTED]
========================================================================================

A third Design dynamic input routine, sitting alongside "Targeted STDP synaptic
strength" (InputDesignerDialog) and "Minimal stimulus for spiking (rheobase)"
(RheobaseDialog). It traces the classic STDP learning window for ONE synapse:
the change in synaptic efficacy as a function of the pre→post spike timing
difference Δt — potentiation (LTP) for Δt > 0 (pre before post) and depression
(LTD) for Δt < 0 (post before pre).

Unlike the other two routines, this is NOT a converging search (no bisection).
It is a DETERMINISTIC SWEEP over a predetermined list of Δt values. For each Δt
it does one cyclical step, then moves to the next Δt, accumulating the window.

Readout is FUNCTIONAL (EPSP-based), reusing the exact measurement the STDP
routine already uses — NOT the raw weight. State handling is APPEND +
RUN-FORWARD with a recovery lead (the model we standardised on for rheobase),
NO store/restore.

────────────────────────────────────────────────────────────────────────────────────────────
WHAT THE ROUTINE MEASURES
────────────────────────────────────────────────────────────────────────────────────────────

For a chosen presynaptic neuron `pre` and postsynaptic neuron `post`, the
routine reports, per tested Δt, the fractional change in the postsynaptic EPSP
amplitude caused by a single pre/post pairing at that Δt:

    ΔEPSP%(Δt) = 100 * (EPSP_after - EPSP_before) / EPSP_baseline

EPSP amplitude is measured exactly as the STDP routine measures it: a
five-pulse presynaptic probe (`PROBE_PULSES = 5`, `PROBE_PERIOD_MS = 100`)
whose postsynaptic response is scored with `detect_epsps` via `_measure_epsps`.

Sign convention (Δt = t_post − t_pre):
    Δt > 0  → pre before post → expect LTP (ΔEPSP% > 0)
    Δt < 0  → post before pre → expect LTD (ΔEPSP% < 0)

The pre/post pulses in a pairing must be SUPRATHRESHOLD so both neurons spike
and drive the synapse's on_pre / on_post pathways (the probe pulses need only
make `pre` spike; the resulting postsynaptic EPSP stays subthreshold). Note in
the log that the amplitude must evoke spikes — point users at the rheobase
routine to find a suprathreshold amplitude first.


────────────────────────────────────────────────────────────────────────────────────────────
WHY NO RESTORE, AND WHY THE RECOVERY GAPS MATTER
────────────────────────────────────────────────────────────────────────────────────────────

Synaptic weight does not passively recover (there is no decay term on `we`), so
the rheobase-style recovery lead cannot return the WEIGHT to a fixed baseline
between Δt points. We deliberately DO NOT use store/restore. Instead the routine
measures the PER-PAIRING change from a rested ELIGIBILITY state:

  - The recovery lead before each block must be ≫ taupre / taupost (default
    150 ms; the example model uses 20 ms time constants, so ~5 τ). This lets the
    `Apre` / `Apost` eligibility traces decay to ~0 before each pairing, so each
    Δt point is an independent single-pairing measurement, and the probe's own
    pre-spikes (which bump `Apre`) do not contaminate the following pairing.

  - Measure EPSP by SUCCESSIVE DIFFERENCES so only one probe is needed per point:
        baseline probe once  → EPSP_0  (also EPSP_baseline for normalisation)
        for each Δt_k:  pairing at Δt_k → probe → EPSP_k
                        ΔEPSP%_k = 100 * (EPSP_k − EPSP_{k-1}) / EPSP_0
    (EPSP_{k-1} is the previous point's probe; EPSP_0 for the first point.)

  - The absolute weight DRIFTS across the sweep. Normalising by EPSP_0 keeps the
    window comparable, but if the running EPSP wanders far from EPSP_0 (e.g.
    < 25% or > 400% of it — a proxy for approaching a `we` clip bound), append a
    one-line saturation warning to the log so the user knows the tail of the
    window is unreliable. Do NOT try to correct the drift; just report it.

PURE HELPERS — src/neuroseq/stdp_window.py (new, no Qt)
────────────────────────────────────────────────────────────────────────────────────────────

1.  delta_t_sweep(dt_min_ms: float, dt_max_ms: float, n_points: int,
                   include_zero: bool = False) -> list[float]

    A sorted list of `n_points` Δt values evenly spaced on [dt_min_ms,
    dt_max_ms]. If `include_zero` is False, drop any value within half a step of
    0.0 (a zero-Δt "pairing" is ill-defined — pre and post coincide). Guard
    n_points < 1 → [] ; n_points == 1 → [midpoint]. Keep it deterministic.

2.  percent_change(before: float, after: float, baseline: float) -> float
        return 0.0 if baseline == 0 else 100.0 * (after - before) / baseline

3.  classify_window(delta_t_ms: float) -> str
        "LTP" if delta_t_ms > 0 else "LTD" if delta_t_ms < 0 else "none"

Trivial, but testing them pins the sweep grid and the sign convention.

────────────────────────────────────────────────────────────────────────────────────────────
SWEEP — the closed-loop state machine (deterministic, NOT bisection)
────────────────────────────────────────────────────────────────────────────────────────────

State on the dialog:
    self._running: bool
    self._awaiting_simulation: bool
    self._phase: str            # "idle"|"initialize_trace"|"baseline_probe"|"pair"|"probe"
    self._delta_ts: list[float]
    self._index: int                    # current Δt index
    self._pairing_repeat: int           # how many pairings applied at the current Δt
    self._baseline_epsp: float | None   # EPSP_0
    self._last_epsp: float | None       # EPSP_{k-1}
    self._pending_delta_t: float
    self._results: list[tuple[float, float]]   # (Δt_ms, ΔEPSP%) in tested order
    self._epsp_trajectory: list[float]         # EPSP amplitude at each probe (drift view)
    self._probe_pulse_times: list[float]       # set by the probe append, used by _measure_epsps

start():
    refresh(); guard project / stim modifier (log + return).
    if not self._confirm_start_over_existing_input(): log "cancelled"; return.
    Validate pre ≠ post; dt_max > dt_min.
    if the trace combo has no simulation voltage trace for `post`:
        phase "initialize_trace"; run an initial 0.001 s sim to create monitors
        (reuse the STDP dialog's initialize_trace flow verbatim); on finish,
        refresh and begin the sweep.
    else begin the sweep.

begin_sweep():
    self._delta_ts = delta_t_sweep(dt_min, dt_max, n_points, include_zero)
    if not self._delta_ts: _finish("No Δt points to sweep."); return
    reset state; log the estimate (~ 1 + n_points*(pairings_per_point + 1));
    self._phase = "baseline_probe"; append a probe; run.

simulation_finished():
    guard running / awaiting; clear awaiting.
    phase "initialize_trace": refresh; if still no trace → _finish; else begin_sweep.
    Otherwise fetch the trace, measure EPSP via _measure_epsps (catch ValueError
    → _finish). Then dispatch on phase:

      baseline_probe:
        self._baseline_epsp = EPSP; self._last_epsp = EPSP
        self._epsp_trajectory.append(EPSP)
        (guard EPSP <= 0 → _finish "Baseline EPSP must be positive.")
        start the first Δt: self._index = 0; self._begin_point()

      probe:                     # a probe that followed a pairing (or repeats)
        self._epsp_trajectory.append(EPSP)
        percent = percent_change(self._last_epsp, EPSP, self._baseline_epsp)
        # Record the change for the CURRENT Δt (after all its pairings).
        self._results.append((self._pending_delta_t, percent))
        self._last_epsp = EPSP
        self._maybe_warn_saturation(EPSP)     # vs 25%..400% of baseline
        self._update_plot()
        self._index += 1
        if self._index >= len(self._delta_ts): _finish(summary); return
        self._begin_point()

    NOTE: "pair" phase runs do NOT measure — after a pairing run completes it is
    handled below (see _begin_point / pairing loop). Only "probe"/"baseline_probe"
    runs measure EPSP.

_begin_point():
    self._pending_delta_t = self._delta_ts[self._index]
    self._pairing_repeat = 0
    self._apply_next_pairing()

_apply_next_pairing():
    append a pairing block at self._pending_delta_t (see BLOCK LAYOUT);
    self._pairing_repeat += 1; self._phase = "pair"; run.
    On the "pair" run's completion (detect in simulation_finished when
    self._phase == "pair"): if self._pairing_repeat < pairings_per_point:
        self._apply_next_pairing()          # another pairing at the same Δt
    else: self._phase = "probe"; append a probe; run.

    (Implement the "pair" completion as an explicit branch at the TOP of
    simulation_finished, before the EPSP measurement, since pairing runs are not
    measured. Keep the phase names exact so tests can drive the loop.)

Log each step, e.g. "Δt +20.0 ms: pairing 1/1", "Δt +20.0 ms → +3.24% EPSP
(LTP)". Use classify_window for the LTP/LTD label.


────────────────────────────────────────────────────────────────────────────────────────────
BLOCK LAYOUTS  (reuse InputDesignerDialog's, adapted)
────────────────────────────────────────────────────────────────────────────────────────────

Probe block — copy `_append_probe`: a recovery lead, then `PROBE_PULSES` pulses
of `pulse duration` on the `pre` column spaced `PROBE_PERIOD_MS`, then a tail of
`post-pulse window` ms. Record `self._probe_pulse_times` from the block start so
`_measure_epsps` can find each pulse. Use the configured Recovery time as the
lead (NOT the STDP dialog's fixed 20 ms) — the eligibility must rest.

Pairing block — copy the body of `_append_pairing`, but take a SIGNED Δt instead
of a `potentiate` bool: lead = Recovery time; `gap_n = round(|Δt| / 1000 / dt)`;
pre pulse first if Δt ≥ 0 else post first; both pulses use `pulse amplitude`.
Reuse `_append_block` (append at max(len, current_sample)) and `_run_to_sample`.

Every appended block goes on the `pre`/`post` columns only; all other columns
stay zero (assert this in tests).

────────────────────────────────────────────────────────────────────────────────────────────
NON-GOALS
────────────────────────────────────────────────────────────────────────────────────────────

- BISECTION / convergence to a target. This routine sweeps a fixed Δt grid.
- store / restore / checkpoint juggling. Append-and-run-forward only; the
  recovery lead rests the eligibility traces (see the rationale above).
- DIRECT WEIGHT readout from the synapse weight matrix. We deliberately chose
  the functional EPSP readout to reuse the validated detect_epsps path and stay
  model-agnostic. (A weight-matrix variant could reuse the same sweep later.)
- Correcting weight drift across the sweep (only report saturation).
- A shared base class with the other dialogs (reuse helpers instead).
- CHANGING gui.py — the editor fan-out already covers the new dialog.
