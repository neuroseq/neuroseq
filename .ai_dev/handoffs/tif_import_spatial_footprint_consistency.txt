tif_import_spatial_footprint_consistency — propagate any new segmentation
from the TIFF calcium-import dialog into the main-window Spatial Footprints
viewer, and warn before running the pipeline with no segmentation at all  [IMPLEMENTED]
================================================================================

Follow-up to suite2p_pipeline_enhancement.txt (issue #506), which added a
third "Auto-detect ROIs with Suite2p (no Cellpose)" mask-source option to
`TifImportDialog`. Two gaps identified since:

  1. `TifImportDialog` can produce/load a NEW cell segmentation two ways —
     browsing a `_seg.npy` file, or Suite2p auto-detection — but neither
     result ever reaches `Project.cellpose_data`, so it never shows up in
     the main window's Spatial Footprints panel (`spatial_footprint_widget`,
     added in the earlier `spatial_footprint_viewer` change). Only the
     THIRD mask source ("Use Cellpose masks from the current experiment")
     is already consistent with the panel, because it reads its masks FROM
     that same project state in the first place (see `_cellpose_result_to_masks`,
     tif_import_dialog.py:33-49) — nothing "new" is produced there.
  2. Running the pipeline in auto-detect mode has no confirmation step, even
     though it's meaningfully less reliable than a human-verified Cellpose
     segmentation (no popup warns the user before proceeding).

Files to change:
    src/neuroseq/tif_import_dialog.py
    src/neuroseq/gui.py

Files to extend (tests):
    tests/test_tif_import_dialog.py
    tests/test_gui.py

BACKGROUND — read before touching anything
────────────────────────────────────────────────────────────────────────────

- The canonical "a new Cellpose-style result just arrived, make the whole
  app consistent" entry point already exists:
  `Gui._apply_cellpose_import_result(self, imported: CellposeImportResult) ->
  list[str]` (gui.py:1210-1253). It clones the result
  (`clone_cellpose_result`), sets `self.last_cellpose_import` AND
  `self.project.cellpose_data`, offers to resize existing stim arrays if the
  new segmentation has more cells (a `QMessageBox.question` — see TESTS for
  how to mock it), and — critically — calls
  `self.spatial_footprint_widget.set_data(self.project.cellpose_data)`
  (gui.py:1251-1252) at the end. This is exactly what needs to be called
  for the two mask sources listed above; do not hand-roll panel refresh
  logic in `tif_import_dialog.py` or `gui.py` — route through this method.
  `btn_import_cellpose_data_clicked` (gui.py:2002-2029) is the existing
  caller to mirror: it calls `_apply_cellpose_import_result`, then
  `self._auto_show_widget(self.spatial_footprint_widget)` guarded by
  `hasattr(self, "_auto_show_widget")` (gui.py:2013-2014) — copy that exact
  guard style, it exists for test doubles that don't define the method.

- `TifImportDialog._resolve_masks()` (tif_import_dialog.py:590-599) has
  three branches, in mask-source-radio order: `_auto_detect_radio` (returns
  `None`), `_use_loaded_radio` (returns `_cellpose_result_to_masks(self._cellpose_import)`
  — i.e. reads FROM the already-loaded `Project.cellpose_data`, so this
  branch produces nothing new to propagate), `_use_seg_radio` (returns
  `_load_masks_from_seg_file(self._seg_file_path)` — genuinely new,
  user-picked file, currently disconnected from `Project.cellpose_data`).

- `TifPipelineResult` (importer_tif.py:53-63) always carries `masks`
  (an (Ly, Lx) int32 label image, 0 = background, 1..N = cells — see the
  suite2p_pipeline_enhancement change for how this is populated in the
  auto-detect case via the new `_stat_to_masks` helper) and `mean_image`
  ((Ly, Lx) float32), REGARDLESS of which of the two pipelines
  (`run_suite2p_pipeline` / `run_roi_average_pipeline`) ran or which mask
  source fed it — both `masks` and `mean_image` are always present. This is
  what makes a uniform "build a CellposeImportResult from this
  TifPipelineResult" helper possible without pipeline-specific branching.

- `CellPoseImporter` (importer_cellpose.py:299-...) is the class that
  normally builds a `CellposeImportResult` from a loaded image + segmentation
  file, and it works entirely off two attributes you can set directly
  instead of going through its file-loading methods:
      importer.image_data          # (Ly, Lx, 3) uint8 RGB, VERTICALLY FLIPPED
      importer.segmentation_data   # (Ly, Lx) int32, background = -1,
                                    # cells = 0..N-1, VERTICALLY FLIPPED
  The vertical flip and the background=-1/0-based-cells convention are the
  same ones `_cellpose_result_to_masks` (tif_import_dialog.py:33-49) already
  documents and undoes for the opposite direction — this change needs the
  FORWARD conversion (raw masks -> CellposeImportResult convention):
      segmentation = masks.astype(np.int32) - 1     # 0->-1 bg, 1..N -> 0..N-1
      segmentation = np.flipud(segmentation)
  `CellPoseImporter._scale_float_image_to_uint8` (importer_cellpose.py:385-400,
  a `@staticmethod`) is the existing float->uint8 min/max normalizer — reuse
  it for `mean_image` rather than writing a new one. After setting
  `image_data`/`segmentation_data` directly, also set
  `importer._segmentation_flipped_for_image = True` (so `_align_orientation_segmentation`,
  if anything ever calls it later, treats the data as already flipped and is
  a no-op — this mirrors what `load_segmentation_file` sets after its own
  flip at importer_cellpose.py:438) and
  `importer._original_cellpose_ids = unique_ids[unique_ids >= 0]` (matches
  the "shifted to 0-based IDs" convention documented at
  importer_cellpose.py:428-431). Then call `importer.generate_overlay()`
  (importer_cellpose.py:474-503, builds `overlay_image` by color-blending
  each cell's ID color from `neuron_indices_to_colors` onto `image_data`) and
  `importer.create_result(image_path=..., segmentation_path=...)`
  (importer_cellpose.py:560-584) to get the final `CellposeImportResult`.
  `create_result`'s other keyword args (`stimulus_to_cellpose_mapping`,
  `mapping_strategy`, `linear_offset`, `aoi_config`) all default sensibly
  (`None`/`"Linear"`/`0`/`None`) — the TIFF dialog has no AOI/custom-mapping
  UI, so leave them at their defaults.

- IMPORTANT — do NOT propagate anything for the `_use_loaded_radio` branch.
  Its masks already ARE `Project.cellpose_data`; rebuilding a fresh
  `CellposeImportResult` from scratch there would silently DROP any existing
  `stimulus_to_cellpose_mapping`/`aoi_config`/`mapping_strategy` the current
  project's Cellpose data carries (e.g. a custom AOI-based stim mapping set
  up via the main Cellpose import dialog) — a real regression, not a no-op.
  Only the `_use_seg_radio` and `_auto_detect_radio` branches produce a
  segmentation that ISN'T already `Project.cellpose_data`, so only those two
  should trigger propagation.

       def _build_cellpose_result_from_pipeline(
           result: TifPipelineResult,
           image_path: Path,
           *,
           segmentation_path: Path | None = None,
       ) -> CellposeImportResult:
           """Wrap a pipeline's masks + mean image as a CellposeImportResult.

           Lets a segmentation that was loaded from a _seg.npy file or
           auto-detected by Suite2p (rather than coming from the main
           Cellpose import dialog) be shown in the Spatial Footprints panel,
           using the same background=-1/vertically-flipped convention
           CellPoseImporter.load_image_file/load_segmentation_file produce.
           """
           importer = CellPoseImporter()
           gray = CellPoseImporter._scale_float_image_to_uint8(result.mean_image)
           importer.image_data = np.flipud(np.stack([gray, gray, gray], axis=-1))
           segmentation = result.masks.astype(np.int32) - 1
           importer.segmentation_data = np.flipud(segmentation)
           importer._segmentation_flipped_for_image = True
           unique_ids = np.unique(importer.segmentation_data)
           importer._original_cellpose_ids = unique_ids[unique_ids >= 0]
           importer.generate_overlay()
           return importer.create_result(
               image_path=image_path, segmentation_path=segmentation_path
           )

NON-GOALS
────────────────────────────────────────────────────────────────────────────

- Propagating anything for the `_use_loaded_radio` branch — see BACKGROUND;
  doing so would regress existing AOI/mapping metadata.
- Any AOI/custom-mapping UI in `TifImportDialog` itself. The propagated
  `CellposeImportResult` always uses the `create_result` defaults
  (`mapping_strategy="Linear"`, `linear_offset=0`, `aoi_config=None`).
- Calling `_warn_if_cellpose_model_mismatch()` (gui.py, used after the main
  Cellpose import dialog) from `btn_import_tif_clicked`. That check is about
  a different concern (Cellpose model name bookkeeping) unrelated to this
  change.
- Changing the "Import successful" message box text in `_finalize_import`.
  The stim-array-resize prompt (if triggered) already surfaces separately
  via `_apply_cellpose_import_result`.
