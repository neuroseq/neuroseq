1. Rewrite `_do_external_simulation`. Replace the current body
   entirely. The pre-flight bookkeeping (cumulative time, tiling,
   stim_dict build, params extraction) stays on the main thread; the
   sim call itself moves into the worker.

```python
def _do_external_simulation(self, simulation_time: float) -> None:
    if self.project.external_simulate_function is None:
        return
    if self._external_sim_worker is not None:
        # Defensive: the Run actions are disabled while a sim is
        # running, so this is unreachable from the UI. Logged so a
        # programmatic re-entry attempt shows up in the log.
        self.logger.warning(
            "External simulation dispatch ignored — a sim is already running."
        )
        return

    # Pre-flight: bookkeeping + stim dict construction on the main
    # thread (touches self.stim_editor and self.project).
    cumulative_so_far = 0.0
    sim = getattr(self.project, "external_simulator", None)
    if sim is not None and hasattr(sim, "simulated_time_seconds"):
        cumulative_so_far = float(sim.simulated_time_seconds)
    target_seconds = cumulative_so_far + simulation_time
    self.project.tile_stim_arrays_to_length(target_seconds)
    self.stim_editor.set_project(self.project)
    stims_dict = {
        k: {"array": v.stim_array.values, "dt": v.stim_array.dt}
        for k, v in self.stim_editor.stims_dict.items()
    }
    params = self.project.external_simulate_params_flat()
    accepts_progress = _external_simulator_accepts_progress(
        self.project.external_simulate_function
    )

    # Capture which project should receive the experiment (the user
    # might switch projects mid-run — see subtle thing C in this
    # chunk). The terminal slot uses this capture, NOT self.project.
    dispatch_project = self.project

    # Progress dialog + cancel button.
    self.progress_dialog.setLabelText("Simulating...")
    self.progress_dialog.setValue(0)
    self.progress_dialog.setCancelButtonText("Cancel")
    self.progress_dialog.show()

    # Cancel plumbing. The dialog's canceled signal is connected to
    # an Event.set; the worker polls the Event from its progress
    # callback.
    self._external_sim_cancel = threading.Event()
    self.progress_dialog.canceled.connect(self._external_sim_cancel.set)

    # Wait cursor — restored in _teardown_external_sim regardless of
    # the terminal path.
    QtWidgets.QApplication.setOverrideCursor(QtCore.Qt.CursorShape.WaitCursor)

    # Prevent re-entry while the worker is busy.
    self._set_simulation_actions_enabled(False)

    # Worker + thread.
    thread = QtCore.QThread(self)
    worker = ExternalSimWorker(
        simulate_fn=self.project.external_simulate_function,
        stims_dict=stims_dict,
        simulation_time=simulation_time,
        params=params,
        accepts_progress=accepts_progress,
        cancel_event=self._external_sim_cancel,
    )
    worker.moveToThread(thread)

    thread.started.connect(worker.run)
    worker.progress.connect(self._on_external_sim_progress)
    # The finished slot needs the dispatch_project capture — wrap.
    worker.finished.connect(
        lambda exp, p=dispatch_project: self._on_external_sim_finished(exp, p)
    )
    worker.cancelled.connect(self._on_external_sim_cancelled)
    worker.failed.connect(self._on_external_sim_failed)
    # Auto-quit the thread on any terminal signal.
    for sig in (worker.finished, worker.cancelled, worker.failed):
        sig.connect(thread.quit)
    thread.finished.connect(worker.deleteLater)
    thread.finished.connect(thread.deleteLater)

    self._external_sim_thread = thread
    self._external_sim_worker = worker
    self.logger.info(
        f"Dispatching external simulation: {simulation_time} s "
        f"(accepts_progress={accepts_progress})"
    )
    thread.start()
```

2. `_teardown_external_sim` helper, next to the slots:

```python
def _teardown_external_sim(self) -> None:
    """Common UI restoration on any terminal signal (finished /
    cancelled / failed). Idempotent."""
    QtWidgets.QApplication.restoreOverrideCursor()
    self.progress_dialog.setCancelButton(None)
    if self._external_sim_cancel is not None:
        try:
            self.progress_dialog.canceled.disconnect(
                self._external_sim_cancel.set
            )
        except (TypeError, RuntimeError):
            # Either the connection wasn't made, or the dialog is
            # mid-teardown. Either way nothing to do.
            pass
    self._external_sim_worker = None
    self._external_sim_thread = None
    self._external_sim_cancel = None
    self._set_simulation_actions_enabled(True)
```

```python
@QtCore.Slot(float)
def _on_external_sim_progress(self, fraction: float) -> None:
    clamped = max(0.0, min(1.0, float(fraction)))
    self.progress_dialog.setValue(int(round(clamped * 100)))

def _on_external_sim_finished(
    self, experiment: Experiment, dispatch_project: Project
) -> None:
    """Worker → main thread: append to the dispatched project.

    `dispatch_project` is the project that owned the simulator at
    the moment of dispatch. If the user has since swapped projects,
    we still land the experiment in the original — anything else
    would silently overwrite the user's now-active project with
    foreign data.
    """
    self._teardown_external_sim()
    self.progress_dialog.setValue(100)
    self.progress_dialog.reset()
    self.logger.info(
        f"External simulation complete: '{experiment.name}' "
        f"{experiment.duration}s, {len(experiment.data)} data objects"
    )
    if self.project is dispatch_project:
        # Common case — current project is still the one that
        # dispatched. Use the existing append flow which surfaces
        # the import dialog and refreshes the GUI.
        self._append_experimental_data(experiment)
    else:
        # The user swapped projects during the run. Push the result
        # to the original project directly (no GUI refresh — that
        # project isn't current) and notify the user.
        dispatch_project.add_experiment(experiment)
        self.logger.warning(
            f"Project swapped during external simulation. Experiment "
            f"'{experiment.name}' was appended to the dispatch-time "
            f"project, not the currently active one."
        )
        QtWidgets.QMessageBox.information(
            self,
            "Simulation finished",
            f"The external simulation finished after a project switch.\n"
            f"Experiment '{experiment.name}' was added to the project "
            f"that started it ('{dispatch_project.project_name or '(unnamed)'}'),"
            " not the project currently open.",
        )

@QtCore.Slot()
def _on_external_sim_cancelled(self) -> None:
    self._teardown_external_sim()
    self.progress_dialog.reset()
    self.logger.info("External simulation cancelled by user.")
    QtWidgets.QMessageBox.information(
        self,
        "Simulation cancelled",
        "Simulation cancelled — no data was added to the project.",
    )

@QtCore.Slot(str)
def _on_external_sim_failed(self, message: str) -> None:
    self._teardown_external_sim()
    self.progress_dialog.reset()
    self.logger.error(f"External simulation failed: {message}")
    QtWidgets.QMessageBox.critical(
        self,
        "External Simulation error",
        f"Could not run external simulation: {message}",
    )
```

`_on_external_sim_finished` takes two positional args (the lambda
in dispatch curries the second). It is therefore not directly
decorated with `@QtCore.Slot(object)` — the lambda is what's
connected to the signal. That's fine; Qt accepts callables.

```python
def closeEvent(self, event):
    # Drain any in-flight external simulation so the worker thread
    # doesn't outlive the GUI.
    if (
        self._external_sim_thread is not None
        and self._external_sim_thread.isRunning()
    ):
        if self._external_sim_cancel is not None:
            self._external_sim_cancel.set()
        # The simulator polls cancel every ~0.1 % of progress, so
        # this should return in milliseconds. Wait up to 2 s; after
        # that, hard-quit the thread (data was going to be
        # discarded anyway because the window is closing).
        if not self._external_sim_thread.wait(2000):
            self.logger.warning(
                "External simulation worker did not stop in 2 s; "
                "force-quitting the thread."
            )
            self._external_sim_thread.quit()
            self._external_sim_thread.wait(1000)

    # ... existing closeEvent body unchanged below this point.
```

SUBTLE THINGS RELEVANT TO THIS CHUNK
────────────────────────────────────────────────────────────────────────────────────────────

A.  Queued connections. Qt picks queued automatically because the
    worker is on a different thread. Do NOT pass
    `Qt.DirectConnection`. The lambda for `finished` is connected
    cross-thread, so it too is queued — the lambda body runs on the
    main thread, which is what we need.

B.  Dispatch-project capture. `self.project` may change between
    dispatch and completion. The wrapper lambda captures
    `dispatch_project` at dispatch time and passes it into the
    slot. The slot uses the capture, NOT `self.project`. Failing to
    do this lets a long-running ELiSe run land its result in
    whatever project the user has since loaded — a silent data
    corruption hazard. The tests below cover this.

C.  `Elise` simulator state on the project (e.g.
    `project.external_simulator.simulated_time_seconds`). The
    worker mutates this on the worker thread during the sim. If a
    main-thread code path were to *read* this field during the run,
    we'd race. As of today no main-thread code does. If you add
    such a read in a later feature, you'll need a lock.

D.  `progress_dialog.canceled` is a signal, not a method. Wire it
    via `self.progress_dialog.canceled.connect(
    self._external_sim_cancel.set)`. The teardown disconnects it
    inside a `try/except (TypeError, RuntimeError)` — Qt raises one
    of those if the connection no longer exists.

E.  `setCancelButton(None)` on teardown. The progress dialog is
    shared with other long-running paths (load project, import).
    Leaving it cancellable after the sim ends would let the user
    accidentally cancel a project save. Restore `None` every time.

F.  `Experiment` object passes through the signal as-is (Qt does
    not deep-copy `object`-typed arguments). The worker stops
    owning the arrays after `emit`; the main-thread slot takes
    ownership. Don't manually free anything.

G.  Reset semantics. If the user cancels and then immediately
    clicks Run again, the simulator resumes from the post-cancel
    state (not from zero), because `Elise.simulate` doesn't reset
    on exception. This is the existing behaviour and is desirable.
    Do NOT add a reset on cancel.

H.  pytest-qt sync. Tests must use `qtbot.waitSignal` to
    synchronise on terminal worker signals. Polling / sleep is
    forbidden — it makes tests flaky on slow CI.

I.  `_append_experimental_data` shows an import dialog. The autouse
    `patch_b2w_exec_show` fixture in `conftest.py` replaces `.exec()`
    with `.show()` on QDialog, so the import dialog won't block.
    Tests for the finished path need to assert the experiment was
    added to the project, not that the dialog showed something.
