elise_opsin_migration — Two virtual-opsin stim arrays replace `u_inp` + `clamp_visible`
========================================================================================

Replace the ELISE wrapper's single `u_inp` stim (a per-step target voltage)
with **two stim arrays** — one for an excitatory virtual opsin, one for an
inhibitory virtual opsin — and **delete `clamp_visible`**, which becomes
mathematically obsolete and was always a source of view/state desync.

The current ELISE wrapper has two problems that this migration solves at the
same time:

  (a) `u_inp` cannot express "no teaching" — no value of `u_inp` produces zero
      teaching conductance under upstream's eq. 17/18 (paper §5.3.3). The
      only escape is the upstream `if u_inp is not None:` gate, which the
      wrapper hits via the `clamp_visible` boolean param. That parameter is
      orthogonal to the stim contents, so the stim widget and the simulator
      can disagree about what is being delivered ("clamp off but heatmap
      shows pattern playing").

  (b) Teaching synapses with reversals `E_exc = 0 mV` / `E_inh = -75 mV` are
      structurally identical to two parallel opsins. Exposing the user-facing
      stim API as "two opsin activations" instead of "one voltage" aligns the
      ELISE plugin with the rest of neuroseq's optogenetic conventions, and
      makes the stim widget the canonical source of truth for what the
      network is being driven with.

The migration is bounded: the upstream `elise` package is untouched. The
wrapper still calls `Network(...)` and still passes `u_inp` to it; the
wrapper just derives `u_inp` from two new stim arrays instead of reading a
single one.

────────────────────────────────────────────────────────────────────────────────────────────
DESIGN — the two-stim, ratio-only parameterisation
────────────────────────────────────────────────────────────────────────────────────────────

The user authors two stim arrays of equal shape `(T, num_vis)`:

    stims_dict["opsin_exc"]["array"]   # excitatory virtual opsin activation, float32
    stims_dict["opsin_inh"]["array"]   # inhibitory virtual opsin activation, float32

Values are interpreted as **fractional activations** in [0, ∞); only their
RATIO matters per-pitch per-timestep (see "magnitudes" below). For each
visible neuron k at each timestep, the wrapper computes:

    sum_k = g_exc_k + g_inh_k
    if sum_k > 0:
        u_tgt_k = (g_exc_k * E_exc + g_inh_k * E_inh) / sum_k
    else:
        u_tgt_k = sentinel for "no teaching for this pitch"

A pitch with both opsins at zero is held at neuroseq's `E_l` (= the
"rest" reference for ELISE) by setting `u_tgt_k = E_l`. This is NOT the
same as "no teaching anywhere" — that requires every pitch to be zero.

If EVERY pitch has `sum_k == 0` at this step, the wrapper passes
`u_inp = None` to `Network.__call__`, taking the upstream's
`if u_inp is not None:` gate and producing literally no teaching current
(this is the replacement for `clamp_visible=False`). The stim widget
naturally shows the all-zero state — view and state agree.

WHY RATIO-ONLY: the upstream constraint (paper §5.3.3 eq. 16) fixes
`g_exc(u) + g_inh(u) = λ/(1−λ) · (g_l + g_den)`. The wrapper doesn't
loosen this — it would require forking upstream. So when the user
provides arbitrary `(g_exc_k, g_inh_k)`, only their ratio is honoured.
The magnitudes are normalised away by the division. The user-facing
docs and tooltip on the opsin stims must say so:

    "Both opsin stim values represent fractional activation; only the
    ratio between excitatory and inhibitory determines the teaching
    target voltage. The overall teaching strength is controlled by the
    `lam` simulation parameter."

WHY DELETE clamp_visible (rather than keep as convenience): with the new
parameterisation, "no teaching anywhere" is just "both stims all zero"
which the user can author with one click of the new Loop dialog
(create a zero-stim and loop it to the right length) or a `Pad`
operation. Keeping `clamp_visible` would re-introduce the same view/state
desync this migration is designed to fix. The user explicitly endorsed
removal in the discussion that prompted this handoff.

Replace the existing `_build_fuer_elise_pattern` helper with one that
produces two stim arrays. The two arrays should encode the Für Elise
intro such that, when the wrapper computes `u_tgt`, it reproduces the
old per-pitch values: -50 mV for an active pitch, -70 mV for a rest pitch
(the old default pattern's "active" vs "rest").

Ratios derived from the matching-potential formula with `E_exc = 0`,
`E_inh = -75`:

    active pitch  (u_tgt = -50 mV):  g_exc : g_inh = 25/75 : 50/75 = 1 : 2
    rest pitch    (u_tgt = -70 mV):  g_exc : g_inh =  5/75 : 70/75 = 1 : 14

Pick any positive scale; the wrapper only uses the ratio. Use scale 1
for clarity. The new helper:

    _FUER_ELISE_OPSIN_EXC_REST: float = 1.0
    _FUER_ELISE_OPSIN_INH_REST: float = 14.0
    _FUER_ELISE_OPSIN_EXC_ACTIVE: float = 1.0
    _FUER_ELISE_OPSIN_INH_ACTIVE: float = 2.0


    def _build_fuer_elise_opsin_stims(
        tfinal_ms: int = 1920,
        event_ms: int = 10,
    ) -> tuple[np.ndarray, np.ndarray]:
        """Two opsin-activation arrays encoding the Für Elise intro.

        Returns `(stim_exc, stim_inh)` of shape `(tfinal_ms, 13)`. The
        wrapper's matching-potential math turns these into u_tgt = -50 mV
        for active pitches and u_tgt = -70 mV for inactive pitches, which
        reproduces the same teaching as the previous single-stim pattern.

        Background voltages match the upstream `to_biounits` transform:
        rest = E_l = -70 mV, active = E_l + biounits_scale = -50 mV.
        """
        n_p = _FUER_ELISE_N_PITCHES
        stim_exc = np.full(
            (tfinal_ms, n_p), _FUER_ELISE_OPSIN_EXC_REST, dtype=np.float32
        )
        stim_inh = np.full(
            (tfinal_ms, n_p), _FUER_ELISE_OPSIN_INH_REST, dtype=np.float32
        )
        cycle_ms = len(_FUER_ELISE_INTRO) * event_ms
        for cycle_start in range(0, tfinal_ms - cycle_ms + 1, cycle_ms):
            for event_idx, event in enumerate(_FUER_ELISE_INTRO):
                t_start = cycle_start + event_idx * event_ms
                t_end = t_start + event_ms
                pitches = event if isinstance(event, tuple) else (event,)
                for pitch in pitches:
                    stim_exc[t_start:t_end, pitch] = _FUER_ELISE_OPSIN_EXC_ACTIVE
                    stim_inh[t_start:t_end, pitch] = _FUER_ELISE_OPSIN_INH_ACTIVE
        return stim_exc, stim_inh

CHANGES — src/neuroseq/project.py (auto-migrate legacy archives)
────────────────────────────────────────────────────────────────────────────────────────────

Add a hook after `load_NN()` populates `external_simulate_function`, in
`Project.load_NN` (around `project.py:744-756`). When the loaded project
has `external_simulate_path == "neuroseq:elise"` AND `self.stim_arrays`
contains a `u_inp` entry but does NOT contain `opsin_exc`/`opsin_inh`,
auto-migrate by computing the two equivalent stims and replacing
`u_inp`:

    def _migrate_legacy_elise_stim(self) -> None:
        """Convert a single `u_inp` stim into `(opsin_exc, opsin_inh)`.

        Old ELISE archives (pre-opsin-migration) carried one stim named
        `u_inp` with per-pitch target voltages. The new wrapper expects
        two opsin-activation arrays. The migration produces stims whose
        ratio reproduces the old u_inp via the matching-potential
        formula.
        """
        if self.external_simulate_path != "neuroseq:elise":
            return
        if "u_inp" not in self.stim_arrays:
            return
        if "opsin_exc" in self.stim_arrays or "opsin_inh" in self.stim_arrays:
            return
        params = self.external_simulate_params or {}
        E_exc = float(params.get("E_exc", {}).get("value", 0.0))
        E_inh = float(params.get("E_inh", {}).get("value", -75.0))
        old = self.stim_arrays["u_inp"]
        u_inp = np.asarray(old.values, dtype=np.float64)
        denom = E_inh - E_exc
        if denom == 0:
            # pathological config; bail without migrating
            self.logger.warning(
                "Cannot migrate legacy u_inp stim: E_inh == E_exc"
            )
            return
        g_exc_vals = ((E_inh - u_inp) / denom).astype(np.float32)
        g_inh_vals = ((u_inp - E_exc) / denom).astype(np.float32)
        # Clip negatives that arise if u_inp wandered outside [E_exc, E_inh];
        # the upstream model already prefers physically meaningful values.
        np.clip(g_exc_vals, 0.0, None, out=g_exc_vals)
        np.clip(g_inh_vals, 0.0, None, out=g_inh_vals)
        del self.stim_arrays["u_inp"]
        self.stim_arrays["opsin_exc"] = StimArray(
            name="opsin_exc",
            stim_type=StimType.Excitation,
            values=g_exc_vals,
            units="1",
            dt=float(old.dt),
        )
        self.stim_arrays["opsin_inh"] = StimArray(
            name="opsin_inh",
            stim_type=StimType.Inhibition,
            values=g_inh_vals,
            units="1",
            dt=float(old.dt),
        )
        self.logger.info(
            "Migrated legacy ELISE 'u_inp' stim to "
            "'opsin_exc'/'opsin_inh' opsin-activation pair."
        )

Call `self._migrate_legacy_elise_stim()` immediately after `load_NN()`
is invoked from `Project.__init__` for a loaded archive. Don't call it
on the fresh-project path (`Project()` with no `filepath`).

- The "ratio-only" semantics is a deliberate restriction inherited from
  upstream eq. 16. Document it in `Elise`'s class docstring and in the
  user-facing description of the `opsin_exc`/`opsin_inh` stim arrays so
  it doesn't surprise anyone.

- The spec at `.ai_dev/specs/elise_clamp_visible_toggle.md` describes a
  parameter this migration deletes. Don't delete that spec — it's the
  historical record of why the intermediate design existed. Add a
  one-line note at the top:

      > **Superseded by** `.ai_dev/specs/elise_opsin_migration.md`
      > (when written). The `clamp_visible` parameter no longer exists;
      > "release" is expressed by zeroing both opsin stim arrays.

  (The successor spec will be written after this handoff lands and is
  reviewed; that's the "review codex work" → spec promotion step.)

- `Project._migrate_legacy_elise_stim` is the only place that knows about
  the legacy single-stim shape. Keep that knowledge localised — don't
  scatter it into the wrapper or the stim editor. The wrapper itself
  should refuse a `stims_dict` without both `opsin_exc` and `opsin_inh`
  (clear error message). Migration is a load-time concern only.

- `update_params` filtering: the new "drop unknown keys" rule is the
  minimum needed for the `clamp_visible` deletion to be backward-
  compatible. It also future-proofs the schema against further
  param renames/removals, so keep it general (filter against
  `self._default_params_schema.keys()`, not a hard-coded set).

- After migration, the existing "smart simulation time default" tile
  semantics (see `.ai_dev/specs/run_smart_simulation_time.md`) keeps
  working: tiling now extends BOTH opsin stims by the same amount,
  preserving their per-pitch ratio across the new tail. No changes
  required to `Project.tile_stim_arrays_to_length` — it already
  operates uniformly across all stim arrays.

- The Für Elise example's "rest pitches" are now actively driven toward
  -70 mV (the `g_exc=1, g_inh=14` ratio) rather than left at upstream's
  E_l by some other mechanism. This means the network is being told
  "this pitch should be at rest" during training — same as the upstream
  ELISE behaviour but now explicit in the stim. Verify the network
  still trains as expected on the new stim by running the integration
  test branch of `tests/test_elise_smoke.py`.

────────────────────────────────────────────────────────────────────────────────────────────
NON-GOALS
────────────────────────────────────────────────────────────────────────────────────────────

- INDEPENDENT TEACHING STRENGTH PER PITCH. The eq. 16 constraint stays
  global — `lam` controls the overall budget. Adding per-pitch teaching
  strength would require bypassing upstream's teaching pipeline (writing
  our own per-step current injection), which means forking
  `elise.model`. Out of scope.

- REAL OPSIN MODELS (ChR2, halorhodopsin) WITH KINETICS. The "virtual"
  opsins here are instantaneous activation → conductance mappings. Real
  opsins have rise/decay time constants and saturation. A follow-up
  spec would extend the wrapper to optionally consume kinetic-model
  stims; not in this handoff.

- CHANGING `lam` SEMANTICS, OR ADDING `phi(u)` PARAMETERS TO THE GUI.
  This handoff doesn't touch the φ(u) discussion that prompted the
  opsin proposal. The supervisor's separate suggestion to broaden φ
  and shift b → 0 is its own modelling experiment; it changes default
  parameter values but not the wrapper architecture.

- GUI VISUALISATION OF "TEACHING IS ACTIVE" STATE. With the migration,
  the stim widget IS the visualisation — no separate badge or banner
  needed. If a user wants to see "is teaching currently active for any
  pitch?", they look at the stim heatmaps; non-zero = active. Don't
  add a separate indicator.
