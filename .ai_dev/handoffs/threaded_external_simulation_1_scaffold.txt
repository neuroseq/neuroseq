1. The worker class. Lives in `gui.py`, top-level, after
   `SimulationCancelledError` and before
   `_external_simulator_accepts_progress`:

```python
class ExternalSimWorker(QtCore.QObject):
    """Runs an external simulation on a worker QThread.

    The worker is created on the main thread, then moved onto a
    fresh QThread by the dispatcher (see Gui._do_external_simulation
    in chunk 2). The simulator runs in `run()`; cancellation is
    cooperative via a `threading.Event` that the dispatcher sets
    when the user clicks Cancel on the shared progress dialog.

    Communication back to the main thread is exclusively via Qt
    signals (queued connection — Qt picks this automatically because
    sender and receiver live on different threads).

    Slots on the receiving side must not block; the worker is
    free-running and would drop progress updates if a slot stalls
    the event loop.
    """

    progress = QtCore.Signal(float)
    finished = QtCore.Signal(object)   # carries Experiment; declared
                                       # as `object` because PySide6
                                       # can't introspect the
                                       # `Experiment` dataclass for
                                       # signal metatype registration.
    cancelled = QtCore.Signal()
    failed = QtCore.Signal(str)

    def __init__(
        self,
        simulate_fn: Callable,
        stims_dict: dict,
        simulation_time: float,
        params: dict,
        accepts_progress: bool,
        cancel_event: threading.Event,
    ) -> None:
        # NOTE: do NOT pass parent=self / any QObject parent here.
        # The worker is about to be moveToThread()'d; a parent on
        # the main thread would forbid the move.
        super().__init__()
        self._simulate_fn = simulate_fn
        self._stims_dict = stims_dict
        self._simulation_time = float(simulation_time)
        self._params = params
        self._accepts_progress = accepts_progress
        self._cancel_event = cancel_event

    @QtCore.Slot()
    def run(self) -> None:
        def _progress_cb(fraction: float) -> None:
            # Runs on the worker thread. Do NOT touch widgets.
            if self._cancel_event.is_set():
                raise SimulationCancelledError("user cancelled")
            try:
                self.progress.emit(float(fraction))
            except Exception:
                # A broken receiver must not kill the simulation.
                pass

        try:
            if self._accepts_progress:
                experiment = self._simulate_fn(
                    self._stims_dict,
                    self._simulation_time,
                    params=self._params,
                    progress=_progress_cb,
                )
            else:
                experiment = self._simulate_fn(
                    self._stims_dict,
                    self._simulation_time,
                    params=self._params,
                )
        except SimulationCancelledError:
            self.cancelled.emit()
            return
        except Exception as exc:
            # Stringify here — the actual exception type won't
            # necessarily survive marshalling cleanly; the message
            # is what we need. Capture the type name for context.
            self.failed.emit(f"{type(exc).__name__}: {exc}")
            return
        self.finished.emit(experiment)
```

────────────────────────────────────────────────────────────────────────────────────────────
SUBTLE THINGS RELEVANT TO THIS CHUNK
────────────────────────────────────────────────────────────────────────────────────────────

A.  Queued vs direct connections. Qt picks queued automatically when
    sender and receiver are on different threads. Don't pass
    `Qt.DirectConnection` anywhere. Tests must trigger the worker
    via `thread.start()` (which queues the `started → run` call to
    the worker thread); do NOT call `worker.run()` directly from
    the test thread or every test assertion below collapses.

B.  No QObject parent on the worker. If you `moveToThread` an
    object that has a parent on the original thread, Qt either
    refuses or the parent/child invariant breaks. Constructor
    takes no `parent=`.

C.  The worker's `progress.emit(...)` call is safe across threads.
    The emit itself returns immediately; the receiver runs later on
    the main thread's event loop. No locking needed.

D.  `Experiment` is a plain dataclass containing numpy arrays. Qt
    signal marshalling for `object`-typed args ships the Python
    reference across without serialising. The worker's reference
    goes out of scope after `emit`; the main thread's slot takes
    ownership in its parameter. No deep copy, no manual free.

E.  `failed(str)` — never emit the raw exception. Stringify in the
    worker. If you need richer error reporting later, emit
    `traceback.format_exc()` as part of the message.

F.  `SimulationCancelledError` already exists in `gui.py` (it shipped
    with the partial fix). Import it in the worker class via the
    same module scope — no need to redefine.

Worker construction helper:

```python
def _spawn_worker(simulate_fn, *, accepts_progress=True):
    import threading
    from qtpy import QtCore
    from neuroseq.gui import ExternalSimWorker
    thread = QtCore.QThread()
    cancel_event = threading.Event()
    worker = ExternalSimWorker(
        simulate_fn=simulate_fn,
        stims_dict={},
        simulation_time=1.0,
        params={},
        accepts_progress=accepts_progress,
        cancel_event=cancel_event,
    )
    worker.moveToThread(thread)
    thread.started.connect(worker.run)
    return thread, worker, cancel_event
```

Required tests:

1.  `test_worker_runs_on_a_non_main_thread(qtbot)`
    The fake simulator records `threading.current_thread().ident`
    (or `.name`) inside its progress callback. After starting the
    thread and waiting on `worker.finished`, assert the recorded id
    differs from `threading.main_thread().ident`. This is the proof
    the work is *actually* off the main thread.

2.  `test_worker_progress_signals_arrive_in_main_thread(qtbot)`
    Connect a list-appending slot to `worker.progress`. Use
    `qtbot.waitSignal(worker.finished, timeout=2000)`. After
    completion, assert the recorded fractions are monotonically
    non-decreasing and that the slot ran on
    `threading.main_thread()`.

3.  `test_worker_emits_finished_with_experiment(qtbot)`
    `qtbot.waitSignal(worker.finished)` captures the experiment via
    the signal's payload (`blocker.args[0]`). Assert it is an
    `Experiment` with `name == "fake_success"`.

4.  `test_worker_emits_failed_on_simulator_exception(qtbot)`
    Use `_fake_simulate_failure`. `qtbot.waitSignal(worker.failed)`.
    Assert the payload string contains both `ValueError` and
    `kaboom`. Assert `worker.finished` was NOT emitted (use
    `qtbot.assertNotEmitted` or a sentinel slot).

Each test must call `thread.quit()` and `thread.wait(2000)` in
a teardown / finally block to avoid leaking threads.

The tests do NOT need a `Gui` instance — they unit-test the
worker class in isolation. This is the whole point of the chunk:
green these before chunk 2 changes the GUI dispatch.
