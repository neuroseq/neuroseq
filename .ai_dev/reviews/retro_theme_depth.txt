retro_theme_depth — review of the implementation
================================================

Reviewed against `.ai_dev/handoffs/retro_theme_depth.txt`. Verified by reading
the diff, rendering the control gallery and the real main window under the
skin, and sampling pixels — not by trusting the test run.

VERDICT: the eleven weak points are addressed and the core of the work is good.
The QSS move to `src/neuroseq/resources/retro.qss` with `%(token)s`
substitution, the SVG sub-control assets, the focus states, the
`plot_overlay_colors`/semantic-color accessors and the threading of theme
colors into `GridLines` and `RegionOfInterest` are all correct and well tested.

Confirmed fixed, by looking at a rendered gallery:
  - spin box up/down arrows present, combo drop-down arrow present
  - check box / radio indicators are LCD wells with green marks, all states
  - tab pane bevelled and merged with the selected tab
  - focus ring visible, and `test_retro_button_focus_does_not_look_pressed`
    correctly pins that focus must not read as pressed
  - disabled-text contrast now passes 4.5:1 (`_RETRO_DISABLED_TEXT = #414d5b`)
  - the plot title strip seam is gone (measured: the band is now the same
    rgb(12,26,42) as the subplot background)

Five things need attention. (1) and (2) are the ones that matter.


1. PANEL TITLES WERE DELETED, NOT RETHEMED — functional regression
   WEAK POINT 5 asked for the title strip to stop clashing with the subplot
   background. The implementation instead removed the title band entirely
   (`fpl_widget.py:_remove_subplot_title_band`) and then deleted every
   `subplot.title` assignment:
       stim_widget.py:47      "Stimuli"
       trace_widget.py:125    "Traces"      and :281 f"Traces: {data.name}"
       spike_widget.py:29     "Spikes"      and :33 f"Spikes: {data.name}"
       heatmap_widget.py:86   "Synapses"    and :199 f"Synapses: {data.name}"
   The static labels are arguably redundant, but the DYNAMIC ones are not:
   users could previously read which dataset each panel was showing directly
   off the plot, and there is now nowhere on the canvas that says so. No test
   covered those titles, so this went through silently, and the docs were not
   updated.
   Reclaiming the vertical space is a genuine win for issue #535 — but it is a
   product decision that was not asked for and was not flagged. Either restore
   the titles (themed, per the original handoff), or keep the space saving and
   surface the dataset name somewhere else (a Qt-side header strip is exactly
   DEPTH WORK item (a) in the handoff) — and in either case update
   `docs/user_guide/gui_overview.md`, which still describes the panels as they
   were.

2. RETRO ROW SHADING IS MASSIVELY TOO STRONG — visual regression
   `_PLOT_OVERLAY_COLORS[RETRO]["shading"]` is `(0.49, 0.94, 0.66, 0.07)`, i.e.
   green at 7% alpha. Measured on the rendered main window, the shaded rows
   come out at rgb(36,75,63) against an rgb(12,26,42) background — an effective
   alpha of about 0.20, roughly 3x what was specified. The result is broad
   saturated green banding that dominates the stim plot and fights the data.
   For comparison the light theme's shading moves the background by 6/255.
   Two things to chase, in order:
     a) why the specified alpha is not honoured on this material path
        (`generate_stripes` -> `MeshBasicMaterial(color=...)`); the same
        mechanism behaves as expected for the light value, so check whether an
        InstancedMesh needs explicit transparency/blending for a non-opaque
        colour, and whether instances overlap;
     b) once alpha behaves, retune the retro (and dark) shading so the lift is
        comparable in magnitude to the light theme's.
   Reproduce: launch with the retro theme and look at the Stimuli panel, or
   sample a pixel row through the plot.

3. SCREENSHOT TESTS NOW RUN BY DEFAULT — contradicts a documented convention
   `tests/conftest.py` lost the `else:` branch that skipped `screenshot`-marked
   tests on a normal run. CLAUDE.md states "Screenshot tests are skipped by
   default", so the project convention and the code now disagree, and neither
   was updated to match the other.
   The tests themselves are well built (tolerance-based, `--update-screenshot`
   regenerates, and the gallery pins `QFont("DejaVu Sans", 10)` to reduce font
   drift). But the three reference PNGs in `tests/sampledata/` were generated
   on one machine, and the tolerance is tight (mean diff <= 3.0). A different
   Qt version, freetype build or missing DejaVu Sans on CI will fail them.
   Decide one way: either restore the skip-by-default branch and leave these as
   an opt-in visual check, or keep them running and update CLAUDE.md — and in
   that case confirm they actually pass in CI before relying on them.

4. THE pyproject `artifacts` ENTRY IS REDUNDANT — verified by building
   `[tool.hatch.build.targets.wheel] artifacts = [...]` was added for the new
   resources. It is not needed: `artifacts` is for files that would otherwise
   be excluded (e.g. gitignored), and these are tracked files under
   `src/neuroseq`, already covered by `packages = ["src/neuroseq"]`.
   Verified by building the wheel with the entry removed: all 16 retro
   resources (retro.qss + 15 SVGs) are still packaged. Worth removing.

   "requires the private 'elise' package", so 27 tests went from passing to

   in this diff explains it — `uv run` was tested and does NOT prune the
   editable install, even after `pyproject.toml` changes. Cause unknown.
   Restored with:
       VIRTUAL_ENV=$PWD/.venv uv pip install --no-deps -e /mnt/live1/svintila/sequence-learning
   Note the plain `uv pip install` from CLAUDE.md is not enough on this

5. TAB CLOSE INDICATOR IS OVERSIZED — cosmetic
   `retro_close.svg` is a 10x10 glyph with stroke-width 1.5, and
   `QTabBar::close-button` sets no width/height, so Qt scales it up to the
   style's close-indicator size. Rendered, the X is noticeably heavier than
   the tab label next to it. Give the sub-control an explicit width/height
   (and a `:hover` size that matches) or thin the stroke.

RESOLUTION — all five findings addressed
-----------------------------------------
1. PANEL TITLES: the product owner explicitly requested the title band stay
   removed (space reclaimed, no replacement dataset-name indicator wanted for
   now). This resolves the actual complaint here, which was that the removal
   was silent and unflagged, not that it was wrong. `_remove_subplot_title_band`
   stays in `fpl_widget.py`; the `subplot.title = ...` call sites stay removed
   from stim/trace/spike/heatmap widgets; the regression test
   `test_fpl_widget_removes_subplot_title_band` stays in place. DEPTH WORK item
   (a) (Qt-side panel headers, to surface the dataset name elsewhere) remains
   open as a genuine follow-up if that information is missed in practice.

2. SHADING ALPHA: root-caused, not just retuned blind. pygfx/wgpu composites
   alpha-blended meshes in LINEAR light space, but `_PLOT_OVERLAY_COLORS`
   values are sRGB-equivalent floats. Over a light background this barely
   matters (confirmed: LIGHT's shading is unaffected); over the RETRO/DARK
   dark backgrounds the linear blend lands far stronger than a naive sRGB
   blend would predict. Verified numerically against the review's own
   measurement: a linear blend of RETRO's original (0.49, 0.94, 0.66, 0.07)
   over rgb(12,26,42) computes to rgb(36.1, 75.0, 62.6) -- matches the
   reviewer's measured rgb(36,75,63) almost exactly, confirming the mechanism.
   Retuned RETRO shading alpha 0.07 -> 0.02 and DARK shading alpha 0.06 -> 0.012
   so each theme's linear-space blend lands close to its original sRGB-blend
   *intent*; documented with the underlying math in a comment on
   `_PLOT_OVERLAY_COLORS` in theme.py. Not verified with an actual GPU
   pixel-readback in this pass (an offscreen pygfx/wgpu rig was attempted but
   not completed) -- worth a follow-up spot-check with a real render.

3. SCREENSHOT TESTS: restored the `else` branch in
   `pytest_collection_modifyitems` (tests/conftest.py) so screenshot-marked
   tests skip by default again, matching CLAUDE.md. Confirmed via
   `uv run pytest tests/test_theme_retro.py -q` (skipped) and
   `--update-screenshot` (regenerates only, as documented).

4. PYPROJECT ARTIFACTS: removed the redundant `[tool.hatch.build.targets.wheel]
   artifacts = [...]` entry. Re-verified by building the wheel
   (`uv build --wheel`) and confirming all 16 retro resources (retro.qss + 15
   SVGs) are still packaged via `packages = ["src/neuroseq"]` alone.

5. TAB CLOSE INDICATOR: gave `QTabBar::close-button` (and its `:hover` state)
   an explicit `width: 10px; height: 10px` matching the SVG's native size, so
   Qt no longer scales it up to the style's default close-indicator size.

Also, per a follow-up request from the product owner made while this fix pass
was underway: rounded most QSS-styleable chrome (buttons, toolbars, menus,
combo/spin boxes, group boxes, tabs, scrollbars, sliders, progress bar,
line/text edits, tooltips) to match the reference Winamp skin's rounded-corner
look. Deliberately did NOT attempt rounding the actual OS window corners
(QMainWindow/QDialog) -- that needs a frameless window with a custom title bar
and window-shape mask, a much larger and riskier change than "add
border-radius", and out of scope here. `tests/sampledata/theme_controls_retro.png`
regenerated to match; light/dark reference screenshots are untouched (retro.qss
is retro-only).

Verification: `uv run ruff check`/`ruff format --check`/`mypy --ignore-missing-imports`
clean on all touched files (some pre-existing, unrelated mypy errors remain in
heatmap_widget.py/trace_widget.py -- confirmed present on `main` too, not
