ADDITIONAL TASK — CC/VC guidance in Import-stimulus and Import-trace
                  pre-dialogs
=================================================================

The File → Import data menu has two patch-clamp entries whose pre-dialog
currently asks only "Import from:" with a one-item combo of ["Igor2"].
Users new to patch-clamp workflows occasionally get confused about which
channel from a Sutter file goes where.

Add a short convention note inside each pre-dialog's label so the
guidance is visible at the point of decision.

Patch-clamp convention:
  - **Current Clamp (CC):** the experiment injects a current and
    records the resulting voltage.
      → import the CURRENT as a stimulus
      → import the VOLTAGE as a trace
  - **Voltage Clamp (VC):** the experiment commands a voltage and
    records the resulting current.
      → import the VOLTAGE as a stimulus
      → import the CURRENT as a trace

Files to change:
  src/neuroseq/gui.py
  tests/test_gui.py  — only if any existing assertion on the label
                       string needs updating (check via grep).

      software, ok = QtWidgets.QInputDialog.getItem(

(`test_gui_pre_dialog_wrapper_calls_inner_handler_on_accept` and
`test_gui_pre_dialog_wrapper_does_nothing_on_cancel`) monkey-patch
`QInputDialog.getItem` with `lambda *args, **kwargs: (software, True)` —

If you want to lock in the guidance text (recommended so it does not
silently regress), add ONE focused test that asserts both pre-dialogs
pass a label containing the CC and VC guidance strings. Example:

    def test_patchclamp_pre_dialogs_include_cc_vc_convention(
        monkeypatch: MonkeyPatch,
    ) -> None:
        captured_labels: list[str] = []

        def fake_get_item(*args, **kwargs):
            # args = (parent, title, label, items, current_index, editable)
            captured_labels.append(args[2])
            return ("Igor2", False)

        monkeypatch.setattr(QtWidgets.QInputDialog, "getItem", fake_get_item)

        fake_gui: Any = SimpleNamespace(
            btn_import_igor2_wave_clicked=lambda: None,
            btn_import_patchclamp_data_clicked=lambda: None,
        )
        Gui.btn_import_stimulus_patchclamp_clicked(fake_gui)
        Gui.btn_import_trace_patchclamp_clicked(fake_gui)

        assert len(captured_labels) == 2
        stim_label, trace_label = captured_labels
        assert "Current Clamp (CC)" in stim_label
        assert "Voltage Clamp (VC)" in stim_label
        assert "CURRENT is the stimulus" in stim_label
        assert "VOLTAGE is the stimulus" in stim_label
        assert "Current Clamp (CC)" in trace_label
        assert "Voltage Clamp (VC)" in trace_label
        assert "VOLTAGE is the trace" in trace_label
        assert "CURRENT is the trace" in trace_label

NOTES / GOTCHAS
---------------
- `QInputDialog.getItem`'s label IS a QLabel internally, and QLabel
  auto-wraps plain text by default — no `\n` handling gymnastics needed.
  If the rendered spacing looks cramped in practice, you can bump it
  with an extra blank line (already included above before "Import from:").

- Do NOT switch these pre-dialogs to `QInputDialog.getText` or a custom
  subclass — the existing parametrised tests rely on `getItem`'s
  signature, and the single-item combobox is consistent with the other
  import/export pre-dialogs.

- The convention guidance is deliberately asymmetric between the two
  wrappers (one says "is the stimulus" / the other "is the trace") so
  that each dialog answers the exact question the user is about to
  decide. Do not collapse them into a single shared string.
