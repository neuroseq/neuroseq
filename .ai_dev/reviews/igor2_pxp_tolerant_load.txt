MUST-FIX (pre-commit blockers)
------------------------------

1. src/neuroseq/importer_igor2.py:335 — ruff B009

   Current:
       build_filesystem = getattr(packed, "_build_filesystem")
       filesystem = build_filesystem(records)

   Ruff error:
       B009 Do not call `getattr` with a constant attribute value.

   Replace both lines with direct attribute access. The leading underscore
   already signals "private usage"; we don't need the `getattr` indirection
   to communicate it:

       filesystem = packed._build_filesystem(records)  # noqa: SLF001

   The `# noqa: SLF001` silences the "private member access" lint (if
   ruff's SLF001 rule is active on this repo — check pyproject.toml; if
   SLF001 is not enabled, drop the noqa). The comment in the previous
   handoff explaining *why* we touch this private symbol is still valid
   and should remain nearby, so future readers understand the upgrade
   risk.

2. tests/test_importer_igor2.py:14 — ruff F401

       from neuroseq.importer_igor2 import SkippedPxpRecord

   SkippedPxpRecord is never referenced in this test module (the skipped-
   record assertions only read .record_type/.reason strings off the
   returned instances). Remove this import.

   `SkippedPxpRecord` remains used in tests/test_igor_import_dialog.py —
   leave that import alone.


SHOULD-FIX (non-blocking cleanups)

3. src/neuroseq/importer_igor2.py — remove the dead "reference" line and
   the unused local aliases it props up.

   Current (around line 234):
       FolderStartRecord = folder_module.FolderStartRecord
       FolderEndRecord = folder_module.FolderEndRecord
       ...
       _ = (FolderStartRecord, FolderEndRecord, UnusedRecord)

   These three classes are never referenced by name at runtime; they're
   reached only via the `RECORD_TYPE` dict's values, which we already
   capture into the local `RECORD_TYPE` variable. The `_ = (...)` line
   exists solely to prevent F841 warnings for assignments we made
   pre-emptively. That's noise.

   Delete all four lines:
       - `FolderStartRecord = folder_module.FolderStartRecord`
       - `FolderEndRecord = folder_module.FolderEndRecord`
       - `UnusedRecord = record_base.UnusedRecord`
       - `_ = (FolderStartRecord, FolderEndRecord, UnusedRecord)`

   Also drop the corresponding `folder_module = importlib.import_module(
   "igor2.record.folder")` import — nothing else in the function uses it.

   Keep `UnknownRecord = record_base.UnknownRecord` (used as the
   `.get(..., UnknownRecord)` default).

   NB: this contradicts part of the original handoff text, which pre-
   emptively pulled these symbols out. Codex followed the handoff
   correctly; we're now tightening on review.

4. tests/test_importer_igor2.py:527 (
   test_load_igor_pxp_file_recovers_from_real_world_broken_record) —
   strengthen the numeric expectation.

   Current:
       assert len(report.waves) > 50, ...

   The reference file 251118_0.pxp yielded 100+ parseable 1-D waves in
   manual exploration; a drop below ~150 would be a silent regression.
   Tighten to:
       assert len(report.waves) > 150, ...

   If Codex has a different local measurement, pick a number ~20% below
   the observed count — the goal is to catch future regressions that
   silently discard lots of waves, not to be tolerant to small numerical
   noise (there is none, the count is deterministic).

5. tests/test_importer_igor2.py — shape of the "skips multidimensional
   waves" fake filesystem.

   The updated test expects a key of `"root/OneDWave"` now, which matches
   real igor2 behaviour (everything lives under the implicit `root`
   folder). Good. But the test no longer exercises a wave placed inside
   a sub-folder. Add one extra wave in a nested folder in that same test
   so the slash-joined path key exercises folder nesting:

       pxp_path.write_bytes(
           _pack_fake_pxp_record(3, b"wave-2d")
           + _pack_fake_pxp_record(3, b"wave-1d")
           + _pack_fake_pxp_record(1, b"subfolder\x00")
           + _pack_fake_pxp_record(3, b"wave-nested")
           + _pack_fake_pxp_record(2, b"")
       )

   and extend the assertion to expect `"root/subfolder/NestedWave"` as
   well. This protects the folder-walk behaviour — which is the whole
   reason we never skip FolderStart/FolderEnd records — against future
   refactors.
